# ADR-048: One WebSocket carries the browser's live channels

This ADR replaces the run page's Server-Sent Events stream with one WebSocket per browser tab, served by lore-api at `/api/ws`, that multiplexes named channels: a `run` channel forwards an assembly run's pod events and transcript to everyone registered for that run, and a `plan` channel tunnels the plan editor's collaboration protocol, so a navigation from a plan to its run keeps the connection.

## Context

ADR-037 chose SSE for run observability and rejected a WebSocket as a duplex channel nothing needed. Two things changed since. The plan editor ([ADR-047](ADR-047-plans-hosted-by-lore-api.md)) opened the stack's first WebSocket, straight from the browser to lore-api's public host, so the ingress, the token ceremony and the client library the rejection counted as costs are already paid. And the run page and the plan page are one flow — a plan's page links to its run — yet each opened and tore down its own connection on every navigation, and the run page reached lore-api through a Next.js proxy hop the plan page never needed.

On the server, each SSE subscriber held its own `LISTEN` subscription and re-read the database on every notification, so a run with five viewers cost five re-reads per pod event.

## Decision

### One socket, many channels

- lore-api serves one WebSocket upgrade at `/api/ws` on its own listener, beside the plans library's mount, and leaves any other upgrade path to the mount that owns it ([validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L306)).
- Every message is one JSON text frame with a client-chosen channel id. A client opens a channel with `open` (kind `run` or `plan`), closes it with `close`, and sends a plan channel's bytes as base64 with `send`; the server answers `opened`, `frame`, `data`, `closed` with a reason, or `error` with a code. The contract is published in OpenAPI as `LiveClientMessage` and `LiveServerMessage` beside `RunStreamFrame`, with the socket named by a root `x-websocket` extension, so the web-ui reads generated types ([validated by](../apps/lore-api/src/work/assembly-line-station/protocol.test.ts#L11), [validated by](../apps/lore-api/src/work/assembly-line-station/protocol.test.ts#L26), [validated by](../apps/lore-api/src/work/assembly-line-station/protocol.test.ts#L59), [validated by](../apps/lore-api/src/work/assembly-line-station/protocol.test.ts#L79)).
- A message that is not JSON, names an unknown type, opens a run without a token, or carries a non-numeric cursor is refused as `bad_message`; a channel id already open is `channel_in_use`; a ninth channel on one socket is `too_many_channels`; a send or close for a channel the socket does not hold is `unknown_channel`. None of them takes the socket down ([validated by](../apps/lore-api/src/work/assembly-line-station/protocol.test.ts#L46), [validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L250), [validated by](../apps/lore-api/src/work/assembly-line-station/channel-registry.test.ts#L7)).
- The socket pings every 25 seconds and terminates a peer that misses a pong; a socket that goes closes every channel it held, once, and a channel a handler ended itself is forgotten without closing it again ([validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L324), [validated by](../apps/lore-api/src/work/assembly-line-station/channel-registry.test.ts#L19), [validated by](../apps/lore-api/src/work/assembly-line-station/channel-registry.test.ts#L33)).

### The run channel and its feed

- A `run` channel opens with a token lore-api minted for exactly that run. The web tier asks for it at `POST /api/assembly-runs/{id}/stream-token` after checking the person's session and their access to the run's repo, exactly as the plan collab token is minted; the token is bound to the run and the person, only its sha256 is stored in `lore.live_tokens`, it expires after ten minutes, and expired rows are swept as new ones are minted ([validated by](../apps/lore-api/src/transport/routes/assembly-lines/run-stream-token.test.ts#L51), [validated by](../apps/lore-api/src/transport/routes/assembly-lines/run-stream-token.test.ts#L70), [validated by](../apps/lore-api/src/transport/routes/assembly-lines/run-stream-token.test.ts#L80), [validated by](../apps/lore-api/src/integration-tests/live-tokens.test.ts#L32), [validated by](../apps/lore-api/src/integration-tests/live-tokens.test.ts#L44), [validated by](../apps/lore-api/src/integration-tests/live-tokens.test.ts#L59), [validated by](../apps/lore-api/src/integration-tests/live-socket.test.ts#L209)).
- The channel says `opened`, then delivers the viewer's snapshot, its replay from the cursor the open named, and `catchup_complete`, each as a `frame` envelope; a token minted for another run closes it as `unauthorized`, a run that is gone as `not_found`, a run at its viewer cap as `capacity`, and a wire that falls behind the high-water mark as `slow` — while the socket stays usable ([validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L58), [validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L93), [validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L116), [validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L150), [validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L172), [validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L159), [validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L285), [validated by](../apps/lore-api/src/integration-tests/live-socket.test.ts#L219), [validated by](../apps/lore-api/src/integration-tests/live-socket.test.ts#L245)).
- **One feed per assembly run.** The first viewer opens the run's feed, which subscribes ONCE to the notification hub on the run's identity; on every notification it re-reads the named row ONCE and forwards the frame — pod events, transcript rows, task events, CI checks — to every viewer registered for that run. The last viewer to leave closes the feed and its subscription, and the next opens a fresh one ([validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L27), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L40), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L155), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L185), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L204), [validated by](../apps/lore-api/src/work/assembly-line-station/run-channel.test.ts#L194), [validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L179)).
- A viewer that joins a live feed catches up on its own — the snapshot, then the replay from ITS cursor — on the feed's one work chain, so a notification that arrives mid-catch-up is handled after it and a late joiner never receives an event twice ([validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L81), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L105), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L256), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L125)).
- The feed keeps the session's rules: one GitHub read per burst of CI notifications, a re-snapshot of every viewer when the hub resyncs, a viewer dropped alone when it buffers past the high-water mark, a per-run cap of twenty viewers, and every viewer told when a read fails so the next open starts clean ([validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L228), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L273), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L290), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L63), [validated by](../apps/lore-api/src/work/assembly-line-station/run-feed.test.ts#L312)).

### The plan channel

- A `plan` channel is the collaboration server's connection wearing the socket's face: the server sees an object whose `send` becomes a `data` envelope and whose `close` becomes a `closed` one, the client's `send` envelopes become its inbound messages, and the client closing the channel tells the collaboration server the client left, once. Auth stays where it was — the Hocuspocus handshake inside the tunnel carries the plan's collab token — so a minted token authenticates and a forged one is refused with the library's own permission-denied message ([validated by](../apps/lore-api/src/work/assembly-line-station/plan-channel.test.ts#L56), [validated by](../apps/lore-api/src/work/assembly-line-station/plan-channel.test.ts#L75), [validated by](../apps/lore-api/src/work/assembly-line-station/plan-channel.test.ts#L85), [validated by](../apps/lore-api/src/work/assembly-line-station/live-socket.test.ts#L219), [validated by](../apps/lore-api/src/integration-tests/live-socket.test.ts#L263)).

### The browser side

- The web-ui holds one socket client per tab in a provider above every page, built from `LORE_WS_URL` (or derived from `LORE_API_URL` next to a local lore-api); without an address there is no client and every page falls back to polling ([validated by](../apps/web-ui/src/lib/live-socket-url.test.ts#L5), [validated by](../apps/web-ui/src/lib/live-socket-url.test.ts#L14), [validated by](../apps/web-ui/src/lib/live-socket-url.test.ts#L20), [validated by](../apps/web-ui/src/app/assembly-runs/[id]/RunVisualizationPanel.test.tsx#L179)).
- The client's reconnect and resubscribe logic is a pure reducer. The first channel connects the socket; a channel requested on an open socket is sent at once and reads `live` when the server says `opened`; a channel requested while the socket is still connecting waits; a released channel is closed on the wire and the socket stays open with no channels, which is what makes a plan-to-run navigation reconnect-free ([validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L31), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L62), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L89), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L110), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L120), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L118)).
- A dropped socket backs off with the same exponential schedule the SSE hook used, tells every channel it is reconnecting, and re-opens them all when it returns; with no channel waiting it goes idle; after the sixth failure it gives up, tells every channel it is offline, and connects afresh for the next request. A channel the server closes as `unauthorized`, `not_found` or `client` ends for good; one closed as `slow`, `server` or `capacity`, or whose token could not be fetched, re-opens after a pause ([validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L134), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L164), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L176), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L215), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L230), [validated by](../apps/web-ui/src/lib/live-socket/connection-machine.test.ts#L260)).
- The client runs the reducer's effects and nothing else: it opens the socket, sends a run open with a token fetched fresh for every open and the newest cursor seen, routes frames and tunnelled bytes to the channel they name, sends a plan channel's bytes only while that channel is open, and ignores events from a socket it has already replaced ([validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L47), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L71), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L102), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L151), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L193), [validated by](../apps/web-ui/src/lib/live-socket/client.test.ts#L222), [validated by](../apps/web-ui/src/lib/live-socket/protocol.test.ts#L10), [validated by](../apps/web-ui/src/lib/live-socket/protocol.test.ts#L30), [validated by](../apps/web-ui/src/lib/live-socket/protocol.test.ts#L36), [validated by](../apps/web-ui/src/lib/live-socket/protocol.test.ts#L46), [validated by](../apps/web-ui/src/lib/live-socket/protocol.test.ts#L61)).
- The run page's token comes from a server action that climbs the same ladder every run proxy climbs — a signed-in person, a run that exists, GitHub's word that they may see its repo — before asking lore-api to mint ([validated by](../apps/web-ui/src/app/assembly-runs/[id]/live-actions.test.ts#L43), [validated by](../apps/web-ui/src/app/assembly-runs/[id]/live-actions.test.ts#L55), [validated by](../apps/web-ui/src/app/assembly-runs/[id]/live-actions.test.ts#L64), [validated by](../apps/web-ui/src/app/assembly-runs/[id]/live-actions.test.ts#L77)).
- The plan editor is handed the shared socket as Hocuspocus's `WebSocketPolyfill`: every instance the provider constructs opens one `plan` channel, reports open once the server says so, delivers tunnelled bytes as message events with an `ArrayBuffer`, reads a lost socket as an error and an abnormal close so Hocuspocus's own retry constructs a fresh instance, and closes its channel on the wire once ([validated by](../apps/web-ui/src/lib/live-socket/channel-websocket.test.ts#L37), [validated by](../apps/web-ui/src/lib/live-socket/channel-websocket.test.ts#L59), [validated by](../apps/web-ui/src/lib/live-socket/channel-websocket.test.ts#L73), [validated by](../apps/web-ui/src/lib/live-socket/channel-websocket.test.ts#L86)).

## Consequences

- The SSE route `GET /api/assembly-runs/{id}/stream`, the web-ui's session-authenticated SSE proxy and the `EventSource` hook are deleted. The browser reaches lore-api's socket directly at its public host, as the plan editor already did; the web-ui nginx ingress and its 60-second read timeout are no longer on the path.
- The run stream's contract, cursor semantics and Postgres `NOTIFY` fan-out are unchanged; ADR-037's amendments on those points stand. What changed is who listens: one feed per run instead of one session per connection, so a run with N viewers costs one re-read per notification instead of N.
- `LORE_PLANS_WS_URL` becomes `LORE_WS_URL` (`wss://<lore-api host>/api/ws`). Terraform sets it; CI never runs terraform, so the apply must land with the deploy.
- lore-api still runs one replica while plans are live (ADR-047). The run channel is fan-out-safe across replicas, but both channels share one socket, so scaling lore-api needs sticky routing for the socket, not only for plans. No planning-station change was needed for this: the library's `/api/plans/collab` mount stays on the listener, and lore-api tunnels to the same Hocuspocus instance the planning registration returns.
- The plan and run channels live in one feature folder, `apps/lore-api/src/work/assembly-line-station/`, together with the run stream's frames, session reads and notification hub.

## Alternatives

**Keep SSE for runs and only share the plan socket.** Rejected: the plan page and the run page are one flow, and two transports means two reconnect state machines, two auth ceremonies and a proxy hop for one of them.

**Make each run a Hocuspocus document and use its stateless messages.** Rejected: the run stream would depend on the collaboration library's wire protocol and hooks, and a planning-station change would be needed to let non-plan document names through its authenticator. The tunnel needs neither.

**Binary frames with a channel prefix instead of base64 in JSON.** Rejected for now: Yjs updates are small and the first document load is the only large message; one text framing keeps the protocol readable and the OpenAPI contract complete. Revisit if plan documents grow.
