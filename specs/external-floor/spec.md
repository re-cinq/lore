The Floor was rewritten as a standalone engine ([re-cinq/floor](https://github.com/re-cinq/floor)) that stores assembly-line definitions, walks runs, queues work and serves a live socket, and that holds no GitHub client and never calls out. This spec is the first slice of replacing `apps/floor` with it ([ADR-049](../../adrs/ADR-049-external-floor.md)): the three code-review lines run on the external floor, reached only through `@re-cinq/floor-client`, while every other line stays on `apps/floor` until its own slice.

## Background

The external floor assigns three jobs to whoever owns GitHub: start its lines, run a service station for every GitHub action a line takes, and answer its git-credential request. Lore owns GitHub, so those three jobs are this spec. Both floors run side by side: a run is either in `pipeline.assembly_runs` (Lore's Floor) or in the external floor's own database, and the run page reads both.

## The feature-planning pipeline

- FR8.1 — `feature-planning` is a floor pipeline file, `libs/assembly-lines/src/floor-pipelines/feature-planning.yaml`, in the same shape as the review lines: it walks `analyze → plan-pass-end → author → analyse-specs → write → open-spec-pr → merged → decompose → issues → done`, with `validate` reached only by its own `manual.plan.validate` start event rather than an edge, and `plan_id` is its only subject. - FR8.2 — `author` and `spec-pr-merged` are `human` stations — the plan editor and the GitHub PR view are their workers — which is what makes the unbounded `author ↔ analyze`, `author ↔ analyse-specs` and `merged ↔ author` cycles legal without an `iteration_max`: a person decides each pass, so there is no runaway to bound. `plan-pass-end` sits on the forward leg between `analyze` and `author` (catching all three of `analyze`'s outcomes and reporting `always` on to `author`, FR8.5) without changing which end of the cycle is human. `write ↔ analyse-specs` and `issues ↔ decompose` are the two agent-only cycles, and both carry `iteration_max: 1`, the same outcome-edge coverage FR2.12 checks, swept generically for every pipeline in this folder. ([validated by gives every outcome a station declares an edge out of its node, in every pipeline](libs/assembly-lines/src/floor-pipelines/floor-pipelines.test.ts#L838))
- FR8.3 — `spec-write` clones its target with git `access: write`; `author` precedes it on every path in (through `analyse-specs`), so it is never the line's first writer. Its prompt commits and pushes its own branch with `git -C /workspace/target push origin HEAD`, the same shape as `code-review-refine`'s self-push, because nothing else in this line pushes for it. - FR8.5 — `plan-pass-end` (`apps/stations/src/planning/plan-pass-end/`) is a `service` station on every one of `analyze`'s three outcomes, itself reporting `always` on to `author`. A first draft or Regenerate pass carries no `refine` need and settles at once. A Refine round carries the section and hash `author` produced the last time it answered `changes_requested`; `plan-pass-end` reads the LATEST `analyze` visit of the same run (`floorClient().stationRuns.get` then `.list`) and, when that visit did not settle `success`, calls `POST /api/plans/{id}/refine-failed` naming the section — so a Refine that died (a crashed pod, a timeout) tells its person instead of leaving them watching a plan that will never answer. When the analyze pass succeeded it calls `POST /api/plans/{id}/refine-done` with the section and what the ask used (nothing, for an ask that named none), which is what moves the section off "the agent is refining this": the live MCP edits change the plan but do not answer the ask _(amended 2026-10-01: the station closed nothing on success, on the belief that the planning library has no `refine-done` route; it has, the old Floor called it, and without it every Refine on the floor left its section asked for good)_. A post that fails fails the node with what lore-api said. A plan's live "who's here" presence is its own collaboration socket's concern (ADR-048), never a REST call this station makes. `LORE_API_URL` unset is a hard failure, not a silent skip, since settling the Refine is this station's whole job. A `refine` value that will not parse, or that names no slot, reads as a draft: there is no section to tell, and failing the node over it would say nothing to anybody.
