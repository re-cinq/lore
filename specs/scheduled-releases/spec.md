# Feature Specification: Scheduled Releases

| Field    | Value                                         |
|----------|-----------------------------------------------|
| Feature  | Scheduled Releases                            |
| Branch   | feat/93-scheduled-releases                     |
| Status   | Shipped                                       |
| Created  | 2026-11-20                                    |
| Owner    | Platform Engineering                          |

A private repository's main branch is published to its public mirror as versioned releases, on a schedule or on demand, with release notes, one Slack post and an entry on the Changelog tab. This section covers the store the releases are kept in.

## Release settings

- A repo's schedule is `settings.release` next to `public_mirror`: `enabled`, `days` (JS weekdays, Sunday 0), `time` (`HH:MM`) and `timezone` (IANA). ([validated by accepts enabled, Friday 08:30 in Europe/Berlin @07e64686](libs/shared/src/domain/models/repo-settings.test.ts#L5))
- `ReleaseSettingsSchema` refuses a weekday outside 0 to 6, a time that is not `HH:MM`, a timezone `Intl` cannot format in and an `enabled` that is not a boolean. ([validated by refuses a weekday of 7, a time of 9am and the timezone Mars/Olympus_Mons @5e65e76d](libs/shared/src/domain/models/repo-settings.test.ts#L16))
- An absent block resolves to disabled, Monday, 09:00, Europe/Berlin (`resolveReleaseSettings`). ([validated by returns disabled, Monday 09:00 Europe/Berlin when the block is absent @9388e668](libs/shared/src/domain/release-settings.test.ts#L5))
- A partial block keeps what it says and fills the rest. ([validated by keeps the given time and days and fills the timezone @c2201a52](libs/shared/src/domain/release-settings.test.ts#L14))
- A key set to `undefined` takes its default. ([validated by ignores a key set to undefined @a05b0569](libs/shared/src/domain/release-settings.test.ts#L25))
- `releaseEnabled(settings)` is true only for a block with `enabled: true`. ([validated by returns true for a release block with enabled true @89d43253](libs/shared/src/domain/release-settings.test.ts#L39))
- Settings with no `release` block read as not enabled. ([validated by returns false for settings with no release block @5dd4bc49](libs/shared/src/domain/release-settings.test.ts#L31))
- A block without `enabled` reads as not enabled. ([validated by returns false for a release block without enabled @1f9a1532](libs/shared/src/domain/release-settings.test.ts#L35))
- Null settings read as not enabled. ([validated by returns false for null settings @603b675d](libs/shared/src/domain/release-settings.test.ts#L43))
- A `release` block cleared to `null` reads as not enabled and resolves to the defaults. ([validated by returns false for a release block cleared to null @0abe3925](libs/shared/src/domain/release-settings.test.ts#L47), [resolves a release block cleared to null to disabled, Monday 09:00 Europe/Berlin @141db20c](libs/shared/src/domain/release-settings.test.ts#L51))
- The settings schema accepts `public_mirror` and `release` cleared to `null`, which is what the settings route stores when either is cleared. ([validated by accepts public_mirror and release cleared to null @20ded66e](libs/shared/src/domain/models/repo-settings.test.ts#L44))

## Saving the release settings

- The settings route refuses a `release` block whose timezone `Intl` cannot format in with 400 and writes nothing. ([validated by returns 400 for a release block with the timezone Mars/Olympus_Mons @ed00c42d](apps/lore-api/src/transport/routes/repos/repo-settings-mirror.test.ts#L232))
- The settings route refuses a `release` block with a weekday outside 0 to 6 with 400. ([validated by returns 400 for a release block with a weekday of 8 @55a55cf9](apps/lore-api/src/transport/routes/repos/repo-settings-mirror.test.ts#L246))
- The settings route merges the `release` block key by key, so saving `time` keeps `enabled` and `days`. ([validated by merges the release block key by key, keeping enabled when time is saved @0edc39f2](apps/lore-api/src/transport/routes/repos/repo-settings-mirror.test.ts#L255))

## Release store

- `lore.changelog_releases` (migration 0132) holds one row per repository and version: the previous tag, the commit, the bump, the range, the summary, the changes, the release URL, where it was published, when it was announced and when it was written. ([validated by reads back v1.3.0 with its change, bump and no announcement @5a66c664](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L123), [answers null as the latest release of a repo with none @d1247ed0](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L163))
- A second write of the same version replaces its row. ([validated by keeps one row for v1.3.0 written twice, the last summary winning @041e55b1](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L169))
- The store orders a repository's releases by the end of the range each covers, newest first, then by version descending, and answers the latest release and a page of the releases ending before a given instant. ([validated by answers v1.2.1, whose range ends 2026-11-20, as the latest over v1.3.0 ending 2026-11-17 and v1.2.0 ending 2026-11-10 @906ca0e9](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L180), [pages by the end of the range, before v1.3.0's end 2026-11-17 giving v1.2.0 then v1.1.0 @46de7c5e](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L190), [answers v1.3.0, v1.2.0 and v1.1.0 in version order descending when all three end 2026-11-20 @4704902f](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L258))
- The store keeps repositories apart. ([validated by keeps the repos apart, v1.0.0 of another repo not appearing in this one's page @e52bedf7](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L210))
- `claimAnnouncement` answers true to the first caller of a written version and false to every later one, and a rewrite of the version keeps the claim. ([validated by claims the announcement of v1.3.0 once and answers false the second time @a8420878](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L222), [stamps announcedAt on v1.3.0 once claimed @fb37e469](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L233), [answers false when claiming the announcement of v9.9.9, which was never written @71d02c76](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L242), [keeps the claim when v1.3.0 is written again after being announced @af5185d8](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L248))
- A second write of a version keeps the time the version was first written. ([validated by keeps the first write time of v1.3.0 when it is written again @cc4b7b11](libs/shared/src/outbound/project/changelog-releases/changelog-releases.test.ts#L270))

## GitHub release surface

- Tagging a commit creates `refs/tags/<tag>` at that sha in the repository, and a tag that already exists is refused. ([validated by createTagRef posts refs/tags/v1.3.0 at the sha @581d0161](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L56), [creates tag v1.0.0 at a1b2 and lists it @b37a1b20](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L70), [refuses tag v1.0.0 a second time and keeps the first sha @ba8bf0ef](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L78), [createTagRef rethrows GitHub's error for a tag it cannot create @10f728e9](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L139))
- Creating a release sends its tag, name and notes as a published release and answers its id, tag, name, notes, draft flag and URL; a second release for the same tag in the same repository is refused, and the same tag in another repository is independent. ([validated by createRelease sends the tag, name and notes as a published release and answers the record @57c84c8c](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L72), [answers the created release for v1.0.0 with its notes @8e19963f](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L14), [refuses a second release for v1.0.0 in the same repo @4dc0baa6](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L32), [keeps the same tag in another repo apart @82acbc10](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L43))
- Reading a release by tag answers its record, and answers null when the repository has no release for that tag. ([validated by releaseByTag answers the record of v1.3.0 @404d31d0](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L102), [releaseByTag answers null when GitHub has no release for the tag (404) @13fe9ba1](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L109), [answers null for tag v1.0.0 when no release was created @2ab6e61d](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L8))
- Updating a release sends only the fields given and answers the updated record, and an unknown release id is refused. ([validated by updateRelease sends release 77's new notes only @3bd3e76f](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L115), [rewrites the notes of release v1.0.0 and leaves its name @c7ca61f6](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L51), [refuses to update release 99 that does not exist @8f9d99f7](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L64))
- Reading a repository Actions variable answers its value, and answers null when the variable is not set. ([validated by repoVariable answers true for LORE_MIRROR @d2ebef3c](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L129), [repoVariable answers null when the variable is not set (404) @284cb49b](libs/shared/src/outbound/project/lib/platform-github-release.test.ts#L133), [answers null for variable LORE_MIRROR when none was set @42fb4601](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L89), [answers true for variable LORE_MIRROR once seeded with true @69fd76ad](libs/shared/src/outbound/project/lib/github-release-memory.test.ts#L95))

## Publishing to the mirror

- A tag that already sits at another sha on the target is refused first, whatever state the target's main is in. ([validated by refuses with tag-at-other-sha f6a7 when the tag sits at f6a7 @b452710a](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L73), [names the tag conflict first when the head is diverged and the tag sits at f6a7 @e7108a45](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L84))
- A target whose main is not an ancestor of the sha to publish is refused as diverged. ([validated by refuses with target-diverged d4e5 when d4e5 is not an ancestor of a1b2c3 @d5e18cd5](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L62))
- A target whose main and tag are both already at the sha answers already up to date, which is a success. ([validated by is already up to date when the target head and the tag are both a1b2c3 @6f4af4a7](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L51))
- Every other case is a push: an empty target, a target main behind the sha, a target main already at the sha without the tag, or a tag already at the sha with main behind. ([validated by pushes when the target is empty and has no tag @bbed7936](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L7), [pushes when the target head d4e5 is an ancestor of a1b2c3 and has no tag @f23fbe5e](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L18), [pushes the tag alone when the target head is already a1b2c3 and the tag is absent @34dea575](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L29), [pushes when the tag already sits at a1b2c3 but the target head d4e5 is behind @3b7b4804](libs/shared/src/outbound/project/workspace/mirror-push-verdict.test.ts#L40))
- The git adapter fetches both repositories' main into a bare cache, decides with `git merge-base --is-ancestor`, and moves the target's main to the sha and creates the tag there in one atomic push. ([validated by moves the target's main to the second commit and creates v1.0.0 there on a clean push @26476e57](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L70))
- The git adapter pushes into an empty target, creating its main and the tag. ([validated by pushes into an empty target and creates its main and v1.0.0 @3e4b7877](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L84))
- A second identical push answers already up to date and changes no ref. ([validated by answers already up to date and changes no ref when the same push runs twice @93527b11](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L102))
- The git adapter never forces: a target holding a commit the source lacks is refused as diverged with its refs unchanged. ([validated by refuses with target-diverged and leaves the target's refs unchanged when the target holds a commit the source lacks @e6079003](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L113))
- A tag present on the target at another sha is refused with neither ref moved. ([validated by refuses with tag-at-other-sha and moves neither ref when v1.0.0 sits at the first commit on the target @9f966092](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L129))
- A failing git command raises an error naming the subcommand whose message carries no credential from the auth arguments. ([validated by fails with a git ls-remote error free of the token when the target cannot be reached @c56ed745](libs/shared/src/outbound/project/workspace/mirror-push-git.test.ts#L142))
- The in-memory double applies the same verdict as the git adapter to a seeded target and history: it pushes, answers already up to date, refuses a diverged target and refuses a tag at another sha, leaving the target untouched on a refusal. ([validated by moves target main to c2 and creates v1.0.0 when c1 is an ancestor of c2 @ab9f8a15](libs/shared/src/outbound/project/workspace/mirror-push-memory.test.ts#L15), [answers already up to date on a second identical push @d4d38e6b](libs/shared/src/outbound/project/workspace/mirror-push-memory.test.ts#L30), [leaves target main at x9 when it is not an ancestor of c2 @5a77f484](libs/shared/src/outbound/project/workspace/mirror-push-memory.test.ts#L43), [refuses and moves nothing when v1.0.0 sits at c1 @40348f51](libs/shared/src/outbound/project/workspace/mirror-push-memory.test.ts#L58))
