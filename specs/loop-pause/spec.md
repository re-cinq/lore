# Feature Specification: Loop Pause

| Field     | Value                                                                    |
|-----------|--------------------------------------------------------------------------|
| Feature   | Loop Pause                                                               |
| Status    | Implemented                                                              |
| Created   | 2026-10-30                                                               |
| Owner     | Platform Engineering                                                     |
| Builds on | [specs/implementation-loop](../implementation-loop/spec.md)              |
| Story     | [#3998](https://github.com/re-cinq/lore/issues/3998)                     |

When a station runs out of model credit ("Credit balance is too low", or Gemini's spent quota), every loop treated it as a failure of the work in hand: the implementation loop labelled the ticket `lore:blocked`, triage labelled the issue `triage: failed`, and the loop went on picking the next item only to fail it the same way. Nothing about the item was wrong. This feature pauses the loop instead and leaves the item queued, so topping up the account and pressing Resume is all a person does.

## FR1 — A pause holds a loop without touching its switch

- A loop's pause is stored in the repository's settings as `loop_pauses.<loop key>`, holding why, the run that caused it, when, and an optional end (`until`). ([validated by returns the implementation pause stored under loop_pauses @333e1b0c](../../libs/shared/src/domain/loops/loop-pause.test.ts#L15), [validated by reads a settings column handed over as a JSON string @0ddb06ae](../../libs/shared/src/domain/loops/loop-pause.test.ts#L34))
- A missing or malformed pause reads as no pause. ([validated by returns null when the loop has no pause @42bf0975](../../libs/shared/src/domain/loops/loop-pause.test.ts#L23), [validated by returns null for a pause without a reason @264063cf](../../libs/shared/src/domain/loops/loop-pause.test.ts#L28))
- A pause with no end holds until a person resumes the loop; a pause with an end resumes by itself once it passes, with no write needed. ([validated by returns false when there is no pause @6315b108](../../libs/shared/src/domain/loops/loop-pause.test.ts#L47), [validated by returns true for a pause with no end @a65e4421](../../libs/shared/src/domain/loops/loop-pause.test.ts#L51), [validated by returns true until 13:00 and false after it @9649dda7](../../libs/shared/src/domain/loops/loop-pause.test.ts#L55), [validated by reads true again once a pause that ended in 2020 has passed @fef13045](../../libs/shared/src/domain/loops/loop-pause.test.ts#L88))
- While a pause holds, the loop starts no work: every reader a tick or event handler asks whether its loop is on answers no, and the loop's own switch keeps the value its owner set. ([validated by reads implementationLoopEnabled false while its switch stays on @53cce316](../../libs/shared/src/domain/loops/loop-pause.test.ts#L72), [validated by reads autoReviewEnabled false @fc8c1eef](../../libs/shared/src/domain/loops/loop-pause.test.ts#L77), [validated by starts nothing for a repo whose digest loop is paused @66c36931](../../apps/stations/src/work/digest-tick/digest-tick.test.ts#L168))
- A pause holds only its own loop. ([validated by reads triage false and spec upkeep true when only triage is paused @2b3dba20](../../libs/shared/src/domain/loops/loop-pause.test.ts#L81))

## FR2 — Pausing and resuming are merge writes

- Pausing a loop merges its pause into the settings: the repository's other settings and the other loops' pauses survive, and a settings column that holds nothing is treated as empty. ([validated by runs the Postgres contract, or explains why it is skipped @a80f8b2c](../../libs/shared/src/outbound/project/settings/settings-loop-pause.contract.test.ts#L46), [validated by stores the implementation pause and keeps the switch and other settings @ab669b53](../../libs/shared/src/outbound/project/settings/settings-loop-pause.contract.test.ts#L73), [validated by keeps the review pause when the triage loop pauses too @43a73945](../../libs/shared/src/outbound/project/settings/settings-loop-pause.contract.test.ts#L87), [validated by pauses a repo whose settings column is null @cd245492](../../libs/shared/src/outbound/project/settings/settings-loop-pause.contract.test.ts#L116))
- Resuming forgets only that loop's pause. ([validated by forgets only the resumed loop's pause @76db1c6d](../../libs/shared/src/outbound/project/settings/settings-loop-pause.contract.test.ts#L101))
- `DELETE /api/repos/{owner}/{repo}/loops/{key}/pause` (admin) resumes a loop and leaves its switch as it is; a repository with no row answers 404. ([validated by DELETE review pause forgets it and echoes the key @4b5f8ae2](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L153), [validated by DELETE a pause on a repo with no row answers 404 @5546be9c](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L176))
- Switching a loop on also resumes it; switching it off leaves its pause alone. ([validated by PUT implementation on forgets the implementation pause @5025b561](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L132), [validated by PUT merge on writes auto_merge.enabled with no approval asked @a84417d2](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L294), [validated by PUT review off leaves the review pause alone @545bd238](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L143))
- The Loops tab's switch shows the switch, not the pause: a paused loop that is switched on reads as on. ([validated by GET shows a paused implementation loop as switched on @b157a6ab](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L110))

## FR3 — Any station in any loop that runs out of credit pauses that loop

- A failed station visit whose error says the model's credit or quota is spent, or that its vendor's billing account is unpaid, disabled or at its limit (Anthropic, Gemini and Vertex, OpenAI), is a credit failure, whether the visit was an agent pod or a station that called a model itself; a successful visit that merely quoted the message is not. How the run ended does not decide it, since a line may route the failure on to a station that ends the run green; a later success of the same station does, because the credit came back. ([validated by returns the agent visit's credit error @cc03988e](../../libs/shared/src/domain/loops/credit-failure.test.ts#L8), [validated by returns a service station's Gemini quota error @7d06746b](../../libs/shared/src/domain/loops/credit-failure.test.ts#L20), [validated by returns null when the failure is not about credit @e4ae54c1](../../libs/shared/src/domain/loops/credit-failure.test.ts#L31), [validated by returns null for a successful visit that quoted the credit message @11025998](../../libs/shared/src/domain/loops/credit-failure.test.ts#L43), [validated by returns the reproduce visit's credit error when the run went on to label-failed @993be44d](../../libs/shared/src/domain/loops/credit-failure.test.ts#L51), [validated by returns null when the review that ran out of credit succeeded on its retry @7dc82eb3](../../libs/shared/src/domain/loops/credit-failure.test.ts#L63), [validated by returns the review's error when Vertex refused it for an unpaid billing account @57cb852e](../../libs/shared/src/domain/loops/credit-failure.test.ts#L72), [validated by returns anthropic-credit for Vertex's unpaid billing account 403 @e21d44ad](../../libs/shared/src/lib/error-classify.test.ts#L46), [validated by returns anthropic-credit for OpenAI's billing hard limit @2df57aa4](../../libs/shared/src/lib/error-classify.test.ts#L62), [validated by returns anthropic-credit for a GCP project whose billing is disabled @b7b386d9](../../libs/shared/src/lib/error-classify.test.ts#L54), [validated by returns anthropic-credit for OpenAI's inactive billing account @0b15a4dd](../../libs/shared/src/lib/error-classify.test.ts#L70))
- Every floor line names the loop it belongs to, or is listed as belonging to none; a new pipeline file cannot skip the decision. ([validated by returns implementation for implementation-loop @179c6065](../../libs/shared/src/domain/loops/loop-of-line.test.ts#L11), [validated by returns review for every code-review line @763f0029](../../libs/shared/src/domain/loops/loop-of-line.test.ts#L15), [validated by returns merge, triage, upkeep, digest and tickets for their lines @d7b04df5](../../libs/shared/src/domain/loops/loop-of-line.test.ts#L23), [validated by returns null for onboard @96f192b2](../../libs/shared/src/domain/loops/loop-of-line.test.ts#L35), [validated by names every floor pipeline either a loop's line or not a loop @65ac056c](../../libs/shared/src/domain/loops/loop-of-line.test.ts#L39))
- When a run of a loop's line settles with a credit failure, the run-settled station pauses that loop in that repository, with no end, before the loop's next tick. ([validated by pauses the implementation loop of acme/widgets when tdd-round ran out of credit @1955dee2](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L58), [validated by pauses the tickets loop when a spec-tickets service station ran out of quota @090c562c](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L80), [validated by pauses the review loop when Vertex refused the review for an unpaid billing account @bf3bfc23](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L145), [validated by pauses the implementation loop when OpenAI's billing hard limit was reached @497b6ee6](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L159), [validated by pauses the triage loop when reproduce ran out of credit and the run ended green through label-failed @ebfc5589](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L134), [validated by pauses nothing when the round failed on red tests @2d92c785](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L94), [validated by pauses nothing when an onboard run ran out of credit @07a035d6](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L104), [validated by pauses nothing when the review that ran out of credit succeeded on its retry @1bfbb660](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L114), [validated by hands the settled run on to the next step after pausing @b6ad979f](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L125))
- Other loops keep running: a pause holds only its own loop in its own repository. ([validated by reads triage false and spec upkeep true when only triage is paused @2b3dba20](../../libs/shared/src/domain/loops/loop-pause.test.ts#L81), [validated by pauses the implementation loop of acme/widgets when tdd-round ran out of credit @1955dee2](../../apps/stations/src/code-review/run-settled/credit-pause.test.ts#L58))

## FR4 — The item a credit failure interrupted stays queued

- The implementation loop neither labels the ticket `lore:blocked` nor counts the failure as an infrastructure deferral; it records why on the task and comments once on the issue that the loop paused and the ticket stays queued. ([validated by requeues a ticket whose tdd-round ran out of credit: no label, one comment saying the loop paused, its reason on task-1, and the re-arm @0512e751](../../libs/shared/src/work/backlog/loop-run-closed.test.ts#L605), [validated by requeues a plan's task that ran out of credit without labelling it @e8bf6b79](../../libs/shared/src/work/backlog/loop-run-closed.test.ts#L641), [validated by counts an earlier run that ran out of credit as no infrastructure failure @8af9e7cd](../../libs/shared/src/work/backlog/loop-run-closed.test.ts#L659), [validated by reads a verdict that ran out of credit as requeued @25c185ba](../../libs/shared/src/work/backlog/loop-run-closed.test.ts#L710))
- Issue triage adds no `triage: failed` on a credit failure, neither from the line's `label-failed` station nor when the run settles, so the issue stays waiting for triage and the sweep picks it again once the loop resumes. ([validated by leaves issue 42 unlabelled when the pass failed because the model's credit ran out @fdab82fc](../../apps/stations/src/issue-triage/triage-label/triage-label.test.ts#L151), [validated by leaves issue 42 unlabelled when the run failed because the model's credit ran out @45b536ac](../../apps/stations/src/code-review/run-settled/triage-failed.test.ts#L83))
- A loop started once per item (spec tickets per merged spec, spec upkeep per week) runs again, when it is resumed or switched on, the station of the pausing run whose credit ran out, before it forgets the pause, since nothing else would start that item again; a refused run keeps the pause. The implementation loop and triage pick their items up themselves, and a digest run again would post a day already past beside the next one, so resuming them runs nothing again. ([validated by resumes the tickets loop and runs decompose of run-7 again @91deca31](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L38), [validated by resumes the implementation loop without running anything again, since its tick picks the ticket @21d1c36b](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L48), [validated by resumes the upkeep loop without running anything again when its run has no credit failure left @fe72541f](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L57), [validated by resumes the digest loop without posting its starved day again beside the next one @165c5dbf](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L81), [validated by keeps the tickets pause when the floor refuses to run decompose again @d1eec8c0](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L90), [validated by resumes the upkeep loop without running anything again when it was paused by no run @ac4204d0](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L67), [validated by resumes the tickets loop that was not paused @7b6b3f69](../../apps/lore-api/src/work/loops/resume-loop.test.ts#L74), [validated by returns tdd-round and its error for a round that ran out of credit @e96cbef3](../../libs/shared/src/domain/loops/credit-failure.test.ts#L85))
- The code-review loop keeps approving the pull request without review when credit runs out, so the pull request is not held on an operator problem. ([validated by approves once with the budget notice and succeeds the check for a run whose agent ran out of quota @97afbc66](../../apps/stations/src/code-review/run-settled/station.test.ts#L149))

## FR5 — The Loops tab shows a paused loop

- The Loops route answers each loop's pause while it holds. ([validated by GET shows a paused implementation loop as switched on @b157a6ab](../../apps/lore-api/src/transport/routes/loops/loops.test.ts#L110))
- A paused loop's pill dot is amber while its switch stays on. ([validated by paints a paused loop's dot amber while its switch stays on @459c0c01](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopPicker.test.tsx#L91))
- Under the loop's name the tab says why it is paused, since when, and until when if it has an end, links the run that paused it, and offers Resume; a loop that runs, or is switched off, shows none of it. ([validated by says the loop is paused for model credit and links run-7, which paused it @c843826b](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopPaused.test.tsx#L14), [validated by says until when a pause that ends on 2026-11-03 holds @365d38c8](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopPaused.test.tsx#L30), [validated by shows why a paused loop is held and its Resume under the name, and nothing while it runs @182b9929](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopSwitch.test.tsx#L102), [validated by shows no pause notice while the paused loop is switched off @3810729a](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopSwitch.test.tsx#L123))
- Resume calls the resume route and refreshes the tab; a refused resume says why. ([validated by resumes the loop through the bound action when Resume is clicked @e6680e06](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopPaused.test.tsx#L43), [validated by says why lore-api refused the resume @8546bf82](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/LoopPaused.test.tsx#L56), [validated by resumes the tickets loop and revalidates the Loops tab @53991364](../../apps/web-ui/src/app/repos/[owner]/[repo]/loops/actions.test.ts#L83))

## Out of Scope

- Pausing on a token-usage burst. The pause's `until` exists so such a rule only has to write a pause.
