# Feature Specification: Repository Changelog

| Field    | Value                                         |
|----------|-----------------------------------------------|
| Feature  | Repository Changelog                          |
| Branch   | feat/changelog-tab                            |
| Status   | Shipped                                       |
| Created  | 2026-10-23                                    |
| Owner    | Platform Engineering                          |

Every repository gets a changelog: the work done per week, newest first, each finished week opening with an introduction, in paragraphs, on every feature delivered or updated. The daily Slack digest stays short (one line per person, `specs/daily-digest` FR5) and links here for the full list.

## Problem Statement

The daily digest listed every merged pull request and open issue per repository. People found it too long, and most of them read only their own lines (feedback, 2026-10-23). The full list still matters, read a week at a time and with a few sentences saying what the week delivered, so it moves to a page of its own. Nothing in Lore kept a repository's weeks: GitHub is read for each digest's window and nothing is stored.

## Background: how it runs

On Mondays the stations service starts one `weekly-changelog` run on the external floor per onboarded repository, for the ISO week that just ended. A station collects what merged and closed that week, an agent writes the introduction, and a station stores the week in `lore.changelog_weeks`. The repository's Changelog tab reads the stored weeks and reads the current week live (FR6).

## FR1 — The week

- A week is an ISO week in UTC, keyed `YYYY-Www`, running from Monday 00:00 to the next Monday 00:00. ([validated by returns Monday 2026-10-19 to Monday 2026-10-26 for 2026-W43 @adf34f2d](libs/shared/src/work/changelog/changelog-week.test.ts#L11), [returns Monday 2026-12-28 to Monday 2027-01-04 for 2026-W53 @3a15e246](libs/shared/src/work/changelog/changelog-week.test.ts#L15))
- The finished weeks at a moment are the weeks before the one it falls in, newest first. ([validated by returns 2026-W43 and 2026-W42 on Monday 2026-10-26 at 06:00Z @c562d0f8](libs/shared/src/work/changelog/changelog-week.test.ts#L31), [returns 2026-W53 on Monday 2027-01-04 @dc5344e0](libs/shared/src/work/changelog/changelog-week.test.ts#L38))

## FR2 — What a week holds

- A week holds the pull requests merged in it, each under its author, and the issues closed in it, each under its assignees, newest first. ([validated by lists a merged PR under its author and a closed issue under its assignees, newest first @f7a7f6d1](libs/shared/src/work/changelog/changelog-week.test.ts#L46))
- A change at the next week's Monday 00:00 belongs to the next week. ([validated by leaves out a PR merged at Monday 2026-10-26 00:00Z, the start of the next week @59bcfda0](libs/shared/src/work/changelog/changelog-week.test.ts#L81))
- An issue a pull request of the week closes is listed once, as the pull request. ([validated by lists issue 12 once, as the PR that closes it @c3462b9f](libs/shared/src/work/changelog/changelog-week.test.ts#L93))

## FR3 — The store

- `lore.changelog_weeks` (migration 0118) holds one row per repository and week: the changes, the introduction (empty when there is none) and when it was written. A second write of the same week replaces the first. ## FR4 — The weekly-changelog line

- `libs/assembly-lines/src/floor-pipelines/weekly-changelog.yaml` walks `collect` (service station `changelog-collect`), `intro` (agent station `changelog-intro`) and `store` (service station `changelog-store`). Every outcome of `intro` reaches `store`, so the agent can never block a week, and an empty week goes from `collect` straight to `store`. A failed `collect` or `store` is retried once. ([validated by walks weekly-changelog from collect through intro to store, reaching store on every outcome of intro and straight from an empty collect @2d76f584](libs/assembly-lines/src/floor-pipelines/floor-pipelines.test.ts#L832))
