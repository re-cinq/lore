Tickets come from a spec, not from the plan that happened to write it. The `spec-tickets` assembly line runs on the external floor every time a pull request merges a `specs/<name>/spec.md` into the default branch. It splits the spec into one user story and the task tickets under it, and a later merge of the same spec rewrites the tickets the earlier run filed instead of filing a second set. The feature-planning line stops at the merge of its spec pull request.

## Requirements

### Trigger

- **FR1**: A merged pull request MUST start one `spec-tickets` run for each `specs/<name>/spec.md` it changed, and no other file starts one. ([validated by keeps only specs/<name>/spec.md and drops plan, tasks and nested files](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L48), [validated by starts one spec-tickets run per merged spec, keyed on repo, path and merge commit](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L128))
- **FR2**: A pull request closed without a merge, or merged into a branch other than the repository's default branch, MUST start no run. ([validated by starts nothing for %s](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L162), [validated by is null for a close that names no merge commit](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L27))
- **FR3**: A spec marked Rejected, Retired or Shipped, and a spec the merge deleted, MUST start no run. ([validated by skips a rejected spec, a retired one, a shipped one and one the merge deleted](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L174))
- **FR4**: A run MUST be keyed on the repository, the spec path and the merge commit, so two merges of one spec each get a run and a redelivered merge starts no second one. ([validated by joins repository, spec path and merge commit](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L90), [validated by skips a spec whose run key is already open, so a redelivered merge starts no second run](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L203))
- **FR5**: The stations service MUST start a run from the `github.pull_request.closed` event on a deployment that has a floor. ([validated by starts a spec-tickets run for a merged specs/<name>/spec.md on the default branch](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L36), [validated by reads the merge out of a merged pull request's close](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L17))

### The line

- **FR6**: The line MUST walk `load-tickets`, `decompose`, `issues` and `issue-coverage` to `done`, and end as failed when a step breaks. ([validated by walks spec-tickets from load-tickets through decompose and issues to issue-coverage and done, keyed on the run key](libs/assembly-lines/src/floor-pipelines/floor-pipelines.test.ts#L122))
- **FR7**: The `spec-tickets-load` station MUST give the decompose agent the id, title, issue number and state of every ticket an earlier run filed for the spec. ([validated by lists a filed task by its id, title, issue number and state, without the body](apps/stations/src/spec-tickets/load-tickets/listing.test.ts#L15), [validated by is empty for a spec nothing was filed for](apps/stations/src/spec-tickets/load-tickets/listing.test.ts#L26))
- **FR8**: The tickets of a spec MUST be recognised on every run by a filing key made of the spec's directory name, with no slash for the issue markers to split on. ([validated by is the spec directory name behind a spec- prefix, with no slash for the marker to split on](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L98))
- **FR9**: A rerun MUST rewrite the open tickets it finds, leave closed ones alone, and close the open ones whose task the spec dropped, through the issue filing the planning line shares with issue triage (`apps/stations/src/planning/file-issues/plan-issue-filing.ts`). ([validated by rewrites the issues of an earlier run of the same spec and files no second set](apps/stations/src/spec-tickets/file-issues/station.test.ts#L129))
- **FR10**: The `spec-tickets-coverage` station MUST count every testable statement of the whole spec, not only those one plan wrote, and send the uncovered ones back to decompose. ([validated by reports success with 2 of 2 covered when the tasks name both statements, reading the spec at commit abc123](apps/stations/src/spec-tickets/issue-coverage/station.test.ts#L124), [validated by fails the same way on a spec-tickets run, which names the spec and no plan](apps/stations/src/spec-tickets/issue-coverage/station.test.ts#L205))
- **FR12**: A pull request that changes a spec only by adding, moving or removing its test links, as the weekly spec upkeep does, MUST start no run for it, since the work it describes is built. ([validated by is true when a patch only moves a validated-by link to another line](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L76), [validated by is false when a patch rewords the statement beside its link](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L80), [validated by is false for a patch GitHub left out, since nothing says the change is links only](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L84), [validated by skips a spec whose only change in the pull request is its test links](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L188))
- **FR13**: The `spec-tickets-decompose` agent MUST be told to pass the repository on every `lore_*` call, to read the spec its `spec_path` names, and to keep the ids of the tickets filed for the spec before and never reuse the id of a task it drops. ([validated by tells spec-tickets-decompose to pass repo on every lore call](libs/assembly-lines/src/floor-pipelines/floor-pipelines.test.ts#L189), [validated by has spec-tickets-decompose read the spec its spec_path value names, and keep the ids of the tickets filed for it before](libs/shared/src/outbound/project/agents/agent-defaults-content.test.ts#L850))

### The loop

- **FR14**: _(Added 2026-10-24.)_ Spec tickets is the **Spec tickets** loop of the repository's Loops tab, one entry of the loop registry (`LOOP_KINDS`, specs/implementation-loop). Its switch is `lore.repos.settings.spec_tickets.enabled`, on unless the repository switched it off, so a repository keeps ticketing its merged specs as before the switch existed; it is flipped at `PUT /api/repos/{owner}/{repo}/loops/tickets`. While the loop is off, a merged spec starts no run: the stations starter asks the switch before it reads the pull request's files. ([validated by answers tickets from spec_tickets.enabled, on by default so a repository keeps ticketing its merged specs](libs/shared/src/domain/loops/loop-enabled.test.ts#L74), [validated by lists implementation, review, merge, triage, upkeep, digest then tickets with their full names](libs/shared/src/domain/loops/loop-enabled.test.ts#L91), [validated by starts nothing for acme/widgets while its spec tickets loop is switched off](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L116), [validated by GET lists implementation, review, merge and digest off and triage, upkeep and tickets on for a repo with empty settings](apps/lore-api/src/transport/routes/loops/loops.test.ts#L70), [validated by GET reads each switch from its own settings key](apps/lore-api/src/transport/routes/loops/loops.test.ts#L92))
- **FR15**: _(Added 2026-10-24.)_ The loop's rows come from `GET /api/repos/{owner}/{repo}/spec-tickets`, read from the line's newest runs, one row per spec named by its directory (`widgets` for `specs/widgets/spec.md`, read out of the run's subject key) and titled by its path, with its run's stages: **Current**, a spec being split now; **Parked**, a spec whose newest run did not succeed, with the run's reason; **Recently addressed**, the specs whose newest run succeeded in the last seven days. Only a spec's newest run speaks for it, so a failure a later merge made up for is history. The Backlog and Awaiting merge stay empty, since the loop starts on a merge and files issues rather than pull requests; the board heads the subject column **Spec**, and while the loop is off the Backlog says it starts no run. A repository that is not onboarded is a 404 before the floor is read. ([validated by reads widgets out of key:acme/widgets:specs/widgets/spec.md@abc123, and null out of a plan run's key](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L106), [validated by reads the spec-tickets line's 40 newest runs of re-cinq/lore and answers the widgets run under current](apps/lore-api/src/transport/routes/spec-tickets/spec-tickets.test.ts#L26), [validated by answers 404 for a repo that is not onboarded without reading the floor](apps/lore-api/src/transport/routes/spec-tickets/spec-tickets.test.ts#L64), [validated by puts the widgets spec being split under current, titled by its path and linked to its run](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L27), [validated by parks the billing spec whose newest run failed with its reason, lists widgets ticketed this week under recent, and leaves out a success from 2 weeks ago](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L44), [validated by lets a spec's newer successful run outrank the failed one before it, so billing is recent and not parked](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L73), [validated by draws a spec tickets run as its spec name with why it stopped, linked to its run and to no pull request](apps/web-ui/src/app/repos/[owner]/[repo]/loops/board/board.test.ts#L313), [validated by heads the subject column Spec for the spec tickets loop alone, and says a switched-off loop starts no run](apps/web-ui/src/app/repos/[owner]/[repo]/loops/board/board.test.ts#L341))
