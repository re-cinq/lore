Tickets come from a spec, not from the plan that happened to write it. The `spec-tickets` assembly line runs on the external floor every time a pull request merges a `specs/<name>/spec.md` into the default branch. It splits the spec into one user story and the task tickets under it, and a later merge of the same spec rewrites the tickets the earlier run filed instead of filing a second set. The feature-planning line stops at the merge of its spec pull request.

## Requirements

### Trigger

- **FR1**: A merged pull request MUST start one `spec-tickets` run for each `specs/<name>/spec.md` it changed, and no other file starts one. ([validated by keeps only specs/<name>/spec.md and drops plan, tasks and nested files](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L48), [validated by starts one spec-tickets run per merged spec, keyed on repo, path and merge commit](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L138))
- **FR2**: A pull request closed without a merge, or merged into a branch other than the repository's default branch, MUST start no run. ([validated by starts nothing for %s](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L173), [validated by is null for a close that names no merge commit](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L27))
- **FR3**: A spec marked Rejected, Retired or Shipped, and a spec the merge deleted, MUST start no run. ([validated by skips a rejected spec, a retired one, a shipped one and one the merge deleted](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L185))
- **FR4**: A run MUST be keyed on the repository, the spec path and the merge commit, so a redelivered merge starts no second one; a merge of a spec whose earlier run is still open MUST cancel that run as superseded before starting its own, since the new run reads the branch as it stands and two open runs would each find no tickets and file over each other *(amended 2026-10-31: two merges of `specs/loop-pause/spec.md` five minutes apart filed under the same task ids twice)*. ([validated by joins repository, spec path and merge commit](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L100), [validated by skips a spec whose run key is already open, so a redelivered merge starts no second run](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L214), [validated by cancels the open run of an earlier merge of specs/a/spec.md as superseded and starts one keyed on the new merge](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L230))
- **FR5**: The stations service MUST start a run from the `github.pull_request.closed` event on a deployment that has a floor. ([validated by starts a spec-tickets run for a merged specs/<name>/spec.md on the default branch](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L36), [validated by reads the merge out of a merged pull request's close](apps/stations/src/events/floor-spec-tickets-handlers.test.ts#L17))

- **FR10**: The `spec-tickets-coverage` station MUST count every testable statement of the whole spec, not only those one plan wrote, and send the uncovered ones back to decompose. - **FR16**: _(Added 2026-10-26.)_ The `spec-tickets-decompose` agent MUST set a task's `needs_person` to what a person must do only when the implementation loop cannot do the task from a checkout of the repository: terraform applied, a cloud console, the cluster or Secret Manager changed, a credential made, another repository changed, an outside account, a decision the spec leaves open, a by-hand step on production data. ### Implementation evidence

- **FR22**: Existing-ticket input MUST include each task's current body and acceptance criteria so reconciliation preserves independently reported gaps. Assessment MUST inspect runtime callers and error paths, and MUST NOT infer operational completion from configuration or implementation files. A disagreement between a ticket and its spec remains a task for human reconciliation. ### The loop

- **FR14**: _(Added 2026-10-24.)_ Spec tickets is the **Spec tickets** loop of the repository's Loops tab, one entry of the loop registry (`LOOP_KINDS`, specs/implementation-loop). Its switch is `lore.repos.settings.spec_tickets.enabled`, on unless the repository switched it off, so a repository keeps ticketing its merged specs as before the switch existed; it is flipped at `PUT /api/repos/{owner}/{repo}/loops/tickets`. While the loop is off, a merged spec starts no run: the stations starter asks the switch before it reads the pull request's files. ([validated by answers tickets from spec_tickets.enabled, on by default so a repository keeps ticketing its merged specs](libs/shared/src/domain/loops/loop-enabled.test.ts#L74), [validated by lists implementation, review, merge, triage, upkeep, digest then tickets with their full names](libs/shared/src/domain/loops/loop-enabled.test.ts#L91), [validated by starts nothing for acme/widgets while its spec tickets loop is switched off](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L126), [validated by GET lists implementation, review, merge and digest off and triage, upkeep and tickets on for a repo with empty settings](apps/lore-api/src/transport/routes/loops/loops.test.ts#L70), [validated by GET reads each switch from its own settings key](apps/lore-api/src/transport/routes/loops/loops.test.ts#L92))
- **FR15**: _(Added 2026-10-24.)_ The loop's rows come from `GET /api/repos/{owner}/{repo}/spec-tickets`, read from the line's newest runs, one row per spec named by its directory (`widgets` for `specs/widgets/spec.md`, read out of the run's subject key) and titled by its path, with its run's stages: **Current**, a spec being split now; **Parked**, a spec whose newest run did not succeed, with the run's reason; **Recently addressed**, the specs whose newest run succeeded in the last seven days. Only a spec's newest run speaks for it, so a failure a later merge made up for is history. The Backlog and Awaiting merge stay empty, since the loop starts on a merge and files issues rather than pull requests; the board heads the subject column **Spec**, and while the loop is off the Backlog says it starts no run. A repository that is not onboarded is a 404 before the floor is read. ([validated by reads widgets out of key:acme/widgets:specs/widgets/spec.md@abc123, and null out of a plan run's key](libs/shared/src/work/spec-tickets/floor-spec-tickets.test.ts#L116), [validated by reads the spec-tickets line's 40 newest runs of re-cinq/lore and answers the widgets run under current](apps/lore-api/src/transport/routes/spec-tickets/spec-tickets.test.ts#L26), [validated by answers 404 for a repo that is not onboarded without reading the floor](apps/lore-api/src/transport/routes/spec-tickets/spec-tickets.test.ts#L64), [validated by puts the widgets spec being split under current, titled by its path and linked to its run](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L27), [validated by parks the billing spec whose newest run failed with its reason, lists widgets ticketed this week under recent, and leaves out a success from 2 weeks ago](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L44), [validated by lets a spec's newer successful run outrank the failed one before it, so billing is recent and not parked](apps/lore-api/src/transport/routes/spec-tickets/tickets-queues.test.ts#L73), [validated by draws a spec tickets run as its spec name with why it stopped, linked to its run and to no pull request](apps/web-ui/src/app/repos/[owner]/[repo]/loops/board/board.test.ts#L313), [validated by heads the subject column Spec for the spec tickets loop alone, and says a switched-off loop starts no run](apps/web-ui/src/app/repos/[owner]/[repo]/loops/board/board.test.ts#L341))
