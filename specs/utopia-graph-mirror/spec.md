Every spec, ADR and other markdown document lore-api ingests is also written into Utopia, the knowledge-graph service deployed beside Lore, as the chain it draws from the document: the document, its sections, their statements, and the tests, source files and ADRs each statement links. ADR-052 records why.

## Background

Dgraph holds the traceability graph today and is to be retired. Utopia already runs in the cluster and keeps a typed graph, but it cannot yet answer two of the reads Lore's checks make, so the chain is mirrored there beside Dgraph rather than moved. The mirror is a copy: nothing in Lore reads it yet, and its failure never fails an ingest.

## The ontology

- FR1.1 — The Lore ontology is one turtle file, `libs/shared/src/domain/lore-ontology.ttl`, read beside the module that names it and copied beside `dist` by the build. Its seventeen classes are the kind words a pushed entity carries, each bound in Utopia to the snake_case key of its label. ([validated by binds the seventeen class labels of the chain and its history to their snake_case class keys](libs/shared/src/domain/lore-ontology.test.ts#L9), [validated by reads the turtle file beside the module, which declares every kind word as a class at version 7](libs/shared/src/domain/lore-ontology.test.ts#L36))
- FR1.2 — `LORE_ONTOLOGY_VERSION` is stored with the repo's settings at setup; a change to the turtle's shape bumps it.
- FR1.3 — Version 2 declares the `text` attribute, a string on Section and Statement, and adds Document to the domain of `title`, so the words a statement says and the title of its document are attributes the base knows. ([validated by declares text on Section, Statement, Commit, PullRequest, Issue and Release and title on Document, Commit, PullRequest, Issue and Release, both strings, so a pushed statement's words, a pull request's body and a document's title are attributes the base knows](libs/shared/src/domain/lore-ontology.test.ts#L48))
- FR1.4 — Version 3 declares what a test run says: `violated_by` from Statement to Test, `outcome` a string on Test, Test in the domain of `commit`, and a SourceFile `contains` its Tests; `covers` names its `lines` and `commit` qualifiers. It adds no class. ([validated by declares violated_by from Statement to Test, outcome as a string on Test, Test under commit, and SourceFile containing Test, so a test run's statements are terms the base knows](libs/shared/src/domain/lore-ontology.test.ts#L65))
- FR1.5 — Version 6 declares Lore's classes pairwise `owl:disjointWith`, the form Utopia's importer reads, at the highest class each holds for: Repository, Document, Section, Statement, Test, Code, the four history classes, Release and Tag against one another, Spec against Adr and SourceFile against CodeDefinition. Utopia inherits a declaration down `rdfs:subClassOf`, so every two of the fourteen leaf classes are disjoint, and its containment and type-drift duplicate proposals skip such a pair: a Spec and its Statement, or a SourceFile and its CodeDefinition, whose names contain each other, are never proposed as one entity. ([validated by declares every pair of Lore's leaf classes disjoint, so Utopia never proposes a Spec and its Statement as one entity](libs/shared/src/domain/lore-ontology.test.ts#L195))

## Names

Utopia resolves an entity by its lower-cased name and flags a name that is a substring of another same-class name, so every name carries the repository and the path:

- repository `owner/repo`; document `owner/repo:<path>`; section `owner/repo:<path>#<heading-slug>`, with a repeated heading suffixed `-2`, `-3` in order; statement `owner/repo:<path>#s<ordinal, four digits>`; test `owner/repo:<test path>::<test title>`; source file `owner/repo:<path>`; an ADR a statement links is the same name its own document has. One module (`libs/shared/src/domain/utopia/names.ts`) builds them for every item, so a test run names a test and the statement it validates exactly as a document's links do; a test's title is the one written in its `it()` call, without the describe chain a runner may prefix. ([validated by names the statement and test exactly as the doc mirror names them](libs/shared/src/domain/utopia/coverage/test-report-statements.test.ts#L206), [validated by builds one doc item with the repository, the Spec document and its three sections, duplicate headings deduped as chain and chain-2](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L43))

## The items

- FR2.1 — One document becomes one `doc:<path>` item: Repository `contains` Document; Document `path`, `commit` and `permalink` (`https://github.com/<repo>/blob/<commit>/<path>`); Document `title` (FR2.7); Document `contains` each Section, with the Section's `title`, `text` and `line_start`. A spec's document is a `Spec`, an ADR's an `Adr`, any other markdown document's a `Doc` (FR17.1), and a statement written before the first heading sits directly under that same document, never under a second `Document` of the same name. ([validated by files a statement written before any heading under the Adr document, never a second Document of the same name](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L221), [validated by types an ADR's document as Adr](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L190), [validated by types a README's document as Doc and files its first sentence under its Usage section](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L202))
- FR2.2 — Each statement becomes one `stmt:<path>#<ordinal>` item: its Section `contains` the Statement; the Statement's `line_start`, `permalink` with `#L<line>` and `text` (FR2.6); for every test link, Statement `validated_by` Test with the Test's `title` (FR2.10), `path`, `line_start` when the link carries a line anchor, and `permalink`; for every code link, Statement `implemented_by` SourceFile with its `path`. ([validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L86))
- FR2.3 — A link to a file under `adrs/` is not a code link; it makes the Statement `decided_by` that Adr. ([validated by links a statement to an ADR with decided_by and treats the ADR as no code link](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L146))
- FR2.4 — A statement sits under the last heading before its line, so the second of two same-named sections holds its own statements. Every item carries `doc_time` when the commit's time is known and no `doc_time` otherwise. ([validated by files the sentence under the second chain section as chain-2 and omits doc_time for an undated commit](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L173))
- FR2.5 — An item never exceeds 200 statements or 60 KiB. A statement with more links than fit is split: the first item keeps its id and the rest take `.2`, `.3`, every one repeating the Section and Statement entities. ([validated by splits a statement with 80 test links into four items under 200 statements each that repeat the section and statement entities](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L235))
- FR2.10 — A test link names its Test by the title written in the test's `it()` call, the name a test run gives the same test (FR9.2): the link label after "validated by", without the backticks around it. A label that gives no title (empty, or a `file.test.ts:21` that says where a test once stood) is resolved instead from the test file read at the commit: the title is the last `it`/`test` declared at or above the link's line anchor. A link whose title neither its label nor its source gives links no Test, so no Test is ever named by a file and line. ([validated by names the test behind a context-freshness.test.ts:21 label by the title declared at its #L6 anchor, and a backticked title without its backticks](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L342), [validated by links no test for an empty label or a gone.test.ts:9 label whose source was not read](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L357), [validated by returns the title declared on line 4 when the anchor is line 4](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L31), [validated by returns the enclosing test's title when the anchor is line 9 inside its body](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L37), [validated by returns null when the anchor is line 3, above every test](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L41), [validated by returns the it and test.skip titles with their lines 4 and 8, template placeholders as written](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L19))
- FR2.11 — The mirror reads only the test files whose links' labels give no title, once each, at the document's commit, from the repo's GitHub contents; a file it cannot read gives its links no title. ([validated by returns the context-freshness, other and gone test paths, whose labels name no title, once each](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L369), [validated by reads src/a.test.ts and src/gone.test.ts at the commit and names the a.test.ts:3 link by its it title, linking nothing for the file that is gone](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L96))

## The words

Utopia's search and chat read what an item says: the pushed statements become the chunk it searches and cites, attribute values included. An item holding only names, ids, lines and permalinks gives a question about a spec nothing to answer from, so the prose of specs and ADRs is copied into the items. Code stays linked by path and is never copied.

- FR2.6 — Each Statement carries `text`: its words as written, with the coverage-link parentheticals stripped (`stripCoverageLinks`, the same grammar search uses) and every run of whitespace collapsed to one space. ([validated by gives the statement the text FR1 — Spaced words. with its coverage links stripped and its runs of spaces collapsed](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L266), [validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L86))
- FR2.7 — Each Section carries its heading as `text` beside its `title`, and the Document carries its first top-level (`# `) heading as `title`; a document with no top-level heading has no title. ([validated by builds one doc item with the repository, the Spec document and its three sections, duplicate headings deduped as chain and chain-2](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L43), [validated by titles nothing for a document with no top-level heading, while its section still carries its heading as text](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L274))
- FR2.8 — A statement's text past 4,000 characters is cut to its first 4,000 and an ellipsis, so one statement never pushes its item past the limits of FR2.5. ([validated by cuts a 5,003-character statement to its first 4,000 characters and an ellipsis](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L289))
- FR2.9 — A statement split across items carries its text on the first item only; `.2`, `.3` and the rest repeat the Section and Statement entities without it. ([validated by keeps the text on the first of four split parts and on none of .2, .3 and .4](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L296))

## The push

- FR3.1 — An item is posted to `POST /api/v1/sources/{source}/statements` under the source's own key, as `external_id`, `doc_time`, `e`, `s` and an empty `n`; the answer's `action` is returned. ([validated by posts the item under the source key with external_id, doc_time and an empty notes list, and returns the action](libs/shared/src/outbound/utopia/utopia-client.test.ts#L179))
- FR3.2 — A tombstone is `external_id` plus `deleted: true`, answered `marked_missing`. ([validated by posts a tombstone as external_id plus deleted true and returns marked_missing](libs/shared/src/outbound/utopia/utopia-client.test.ts#L205))
- FR3.3 — A 429 or 5xx is retried once after a short wait; a second failure, or any other refusal, throws a `UtopiaError` carrying the status and the first 300 characters of the body, with no retry. ([validated by retries once after a 503 and returns the second answer](libs/shared/src/outbound/utopia/utopia-client.test.ts#L220), [validated by gives up after two 503s with a UtopiaError carrying the status](libs/shared/src/outbound/utopia/utopia-client.test.ts#L233), [validated by throws a UtopiaError with the status and the first 300 body characters on a 422 without retrying](libs/shared/src/outbound/utopia/utopia-client.test.ts#L244))
- FR3.4 — A document's items are pushed four at a time; the outcome counts the items and how many Utopia created, updated and left unchanged, and names every item whose push threw while the rest still land. ([validated by pushes the doc item and one item per statement and counts created, updated and unchanged](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L41), [validated by names a statement item whose push threw under failed and still pushes the others](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L65))
- FR3.5 — A deleted document is tombstoned: its `doc:` item, and its statement items for the ordinals the caller knows; with none known, the `doc:` item alone. ([validated by tombstones the doc item and the statement items of the ordinals it is given](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L130), [validated by tombstones only the doc item when no ordinals are known](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L148))

## The ingest

- FR4.1 — The deployment reaches Utopia through `UTOPIA_API_URL` (`utopia.enabled` in the lore-api chart, from `enable_utopia`); without it the mirror is off. ([validated by is true with UTOPIA_API_URL set and false without it](libs/shared/src/outbound/utopia/utopia-client.test.ts#L125))
- FR4.2 — A repo is mirrored when its settings name a source in `utopia.source_id`, `lore.utopia_sources` holds the key of that same source, and the deployment has a Utopia; otherwise the ingest mirrors nothing. ([validated by pushes through the stored src-1 key when settings.utopia names src-1 and UTOPIA_API_URL is set](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L26), [validated by is null without UTOPIA_API_URL, without a utopia block, without a stored key, and with a key stored for another source](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L33))
- FR4.3 — After the delta route has projected a `specs` or `adrs` delta into the graph, each file is mirrored as a spec or an ADR at the delta's commit and each deleted path is tombstoned. A default-branch `test-report` delta mirrors its tests (FR9) and a `code` delta its source files (FR10); a branch's report mirrors nothing. ([validated by mirrors a main test-report at the delta's commit after projecting it](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L365), [validated by mirrors nothing for a feat/x test-report delta](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L830), [validated by mirrors a projected spec as kind spec at the delta's commit and unmirrors the deleted one](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L186), [validated by mirrors a main code delta's files after projecting them](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L239))
- FR4.4 — A mirror that fails is logged as `[utopia-mirror] <repo> <path>: <message>`, counted on `lore_utopia_mirror_failures_total` by repo, and never fails the ingest, which answers 200 with what the graph did. ([validated by answers 200 with test_chunks counted when the report mirror throws](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L405), [validated by answers 200 with the projection counted when the mirror throws](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L213), [validated by counts a failed Utopia mirror of re-cinq/lore](libs/shared/src/outbound/otel/metrics.test.ts#L109))

## Setup

## Setup on first ingest

- FR6.1 — A deployment sets repos up itself when it has `UTOPIA_API_URL`, `UTOPIA_TOKEN` (the write token of the Utopia person Lore acts as, a workspace admin) and `UTOPIA_WORKSPACE_ID` (the workspace the bases are created in); missing any one, it does not. ([validated by is true with the URL, the token and the workspace id set, and false when any one of them is missing](libs/shared/src/outbound/utopia/utopia-client.test.ts#L134))
- FR6.2 — On such a deployment, the first mirrored ingest (a spec, an ADR or a default-branch test report) of a repo that FR4.2 would not mirror runs the setup of FR5.1 under that token in that workspace, saves the key to `lore.utopia_sources` and the ids to `settings.utopia` through the same writer the route uses, then mirrors what it ingested to the new source. - FR6.3 — Two ingests of one repo in one lore-api process share one setup: one knowledge base, one source, one saved key. Across processes, the knowledge base found by name and the one-row-per-repo upsert keep the repo at one base; a source created by each is possible, and the key saved last is the one pushed through. ([validated by shares one setup between two concurrent first ingests of re-cinq/lore: one knowledge base, one source, one saved key](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L144))
- FR6.4 — A failed setup is a failed mirror (FR4.4): logged, counted, never an ingest failure. Nothing is stored, and the next mirrored document of the repo tries the setup again. ## Ontology upgrade

A knowledge base keeps the ontology it was set up with until Lore imports a newer one. `settings.utopia.ontology_version` says which it holds; a setting without one reads as older than any version.

- FR8.1 — Before pushing a document of a repo whose stored `ontology_version` is below `LORE_ONTOLOGY_VERSION`, a deployment that can set repos up itself (FR6.1) imports the ontology into the repo's knowledge base under its token, binds every kind word, stores the new version in `settings.utopia`, and pushes. Two ingests of one repo in one process share one upgrade. ([validated by re-imports the ontology into kb-1 once for two concurrent ingests, binds the seventeen kind words, stores version 7, and answers src-1](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L237), [validated by answers the stored src-1 without calling Utopia when settings already name it at ontology version 7](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L165))
- FR8.2 — A deployment without a token pushes without upgrading and leaves the stored version as it is: the new attributes land in the base unbound to the ontology, still searchable. ([validated by answers src-1 and calls Utopia for nothing when the deployment has no UTOPIA_TOKEN, leaving version 1 stored](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L260))
- FR8.3 — A failed upgrade is logged as `[utopia-mirror] <repo> ontology upgrade: <message>` and counted as a failed mirror (FR4.4), the stored version stays, and the push goes ahead; the next ingest tries the upgrade again. ([validated by answers src-1 and counts one mirror failure for re-cinq/lore when Utopia refuses the import with 403, leaving version 1 stored](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L274))
- FR8.4 — An ontology import waits up to five minutes for Utopia's answer, a push or a read 30 seconds. An import plans against the whole base, writes every class and relation and queues alignment, so on a busy base it outlasts a push's wait: with one timeout for both, the version-4 upgrade timed out on every ingest on 2026-10-17 while the base's database sat at its CPU limit. ([validated by waits past the 50ms request timeout for an import Utopia answers after 200ms, while a push that slow is aborted](libs/shared/src/outbound/utopia/utopia-client.test.ts#L311))

## Backfill

A repo whose specs, ADRs and other documents were ingested before the mirror existed, or before it was set up, holds nothing in Utopia until each document changes again. The backfill pushes them all once.

## Weekly backfill

## Commits

The chain says what a repository's documents, tests and code are; the default branch's commits say when each changed, by which pull request, for which issue or Lore task. `commitItems` (`libs/shared/src/domain/utopia/git-history/commit-statements.ts`) turns one commit into an item, lore-api walks the branch above a cursor (`apps/lore-api/src/work/utopia/git-history/utopia-commits.ts`), and the stations post that walk on every push.

A commit item carries the commit's words and links and never the files it changed. Each changed path would be an entity Utopia resolves against the whole base, and a commit touching forty files named forty of them: on 2026-10-17, with Utopia's queue growing, the file list was dropped. ## Pull requests and issues

## Out of scope

- Reading the mirror: the spec pages, the detectors and `query_trace` keep reading Dgraph, and only the `repo` and `adrs` sections of context assembly read through the client of FR11 (FR13).
- Tombstoning the statement items of a deleted document; the ordinals of the last push are not stored yet.
- The text of code: a source file and its definitions are named and linked by their GitHub permalinks, and their contents are not copied into Utopia. Documents are the other way round: every markdown document goes in whole (FR17).
- The files a commit changed, and what it changed inside them: they are read from the repository.
- Commits on any branch but the default one, and the history of a pull request's own commits: a squash merge is one commit.
- A pull request's reviews, its review comments and the conversation on an issue or a pull request: the tracker mirror holds what an issue or a pull request says of itself.
- Tombstoning a deleted issue, release or tag: GitHub's lists no longer return it, so its item stays as it last was.
- Reading memory from Utopia.
- Lore's own fact handling in Utopia: Lore retires a fact that a new one contradicts at 0.92 similarity, where Utopia closes or reviews the contradiction itself, so a later read of Utopia's facts will not match Lore's one for one.
