Every spec and ADR lore-api ingests is also written into Utopia, the knowledge-graph service deployed beside Lore, as the chain it draws from the document: the document, its sections, their statements, and the tests, source files and ADRs each statement links. ADR-052 records why.

## Background

Dgraph holds the traceability graph today and is to be retired. Utopia already runs in the cluster and keeps a typed graph, but it cannot yet answer two of the reads Lore's checks make, so the chain is mirrored there beside Dgraph rather than moved. The mirror is a copy: nothing in Lore reads it yet, and its failure never fails an ingest.

## The ontology

- FR1.1 — The Lore ontology is one turtle file, `libs/shared/src/domain/lore-ontology.ttl`, read beside the module that names it and copied beside `dist` by the build. Its ten classes are the kind words a pushed entity carries, each bound in Utopia to the snake_case key of its label. ([validated by binds the ten class labels of the chain to their snake_case class keys](libs/shared/src/domain/lore-ontology.test.ts#L9), [validated by reads the turtle file beside the module, which declares every kind word as a class at version 2](libs/shared/src/domain/lore-ontology.test.ts#L29))
- FR1.2 — `LORE_ONTOLOGY_VERSION` is stored with the repo's settings at setup; a change to the turtle's shape bumps it.
- FR1.3 — Version 2 declares the `text` attribute, a string on Section and Statement, and adds Document to the domain of `title`, so the words a statement says and the title of its document are attributes the base knows. ([validated by declares text on Section and Statement and title on Document, both strings, so a pushed statement's words and a document's title are attributes the base knows](libs/shared/src/domain/lore-ontology.test.ts#L41))

## Names

Utopia resolves an entity by its lower-cased name and flags a name that is a substring of another same-class name, so every name carries the repository and the path:

- repository `owner/repo`; document `owner/repo:<path>`; section `owner/repo:<path>#<heading-slug>`, with a repeated heading suffixed `-2`, `-3` in order; statement `owner/repo:<path>#s<ordinal, four digits>`; test `owner/repo:<test path>::<test title>`; source file `owner/repo:<path>`; an ADR a statement links is the same name its own document has. ([validated by builds one doc item with the repository, the Spec document and its three sections, duplicate headings deduped as chain and chain-2](libs/shared/src/domain/utopia/doc-statements.test.ts#L43))

## The items

- FR2.1 — One document becomes one `doc:<path>` item: Repository `contains` Document; Document `path`, `commit` and `permalink` (`https://github.com/<repo>/blob/<commit>/<path>`); Document `title` (FR2.7); Document `contains` each Section, with the Section's `title`, `text` and `line_start`. A spec's document is a `Spec`, an ADR's an `Adr`. ([validated by types an ADR's document as Adr](libs/shared/src/domain/utopia/doc-statements.test.ts#L190))
- FR2.2 — Each statement becomes one `stmt:<path>#<ordinal>` item: its Section `contains` the Statement; the Statement's `line_start`, `permalink` with `#L<line>` and `text` (FR2.6); for every test link, Statement `validated_by` Test with the Test's `title` (the link label after "validated by"), `path`, `line_start` when the link carries a line anchor, and `permalink`; for every code link, Statement `implemented_by` SourceFile with its `path`. ([validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/doc-statements.test.ts#L86))
- FR2.3 — A link to a file under `adrs/` is not a code link; it makes the Statement `decided_by` that Adr. ([validated by links a statement to an ADR with decided_by and treats the ADR as no code link](libs/shared/src/domain/utopia/doc-statements.test.ts#L146))
- FR2.4 — A statement sits under the last heading before its line, so the second of two same-named sections holds its own statements. Every item carries `doc_time` when the commit's time is known and no `doc_time` otherwise. ([validated by files the sentence under the second chain section as chain-2 and omits doc_time for an undated commit](libs/shared/src/domain/utopia/doc-statements.test.ts#L173))
- FR2.5 — An item never exceeds 200 statements or 60 KiB. A statement with more links than fit is split: the first item keeps its id and the rest take `.2`, `.3`, every one repeating the Section and Statement entities. ([validated by splits a statement with 80 test links into four items under 200 statements each that repeat the section and statement entities](libs/shared/src/domain/utopia/doc-statements.test.ts#L202))

## The words

Utopia's search and chat read what an item says: the pushed statements become the chunk it searches and cites, attribute values included. An item holding only names, ids, lines and permalinks gives a question about a spec nothing to answer from, so the prose of specs and ADRs is copied into the items. Code stays linked by path and is never copied.

- FR2.6 — Each Statement carries `text`: its words as written, with the coverage-link parentheticals stripped (`stripCoverageLinks`, the same grammar search uses) and every run of whitespace collapsed to one space. ([validated by gives the statement the text FR1 — Spaced words. with its coverage links stripped and its runs of spaces collapsed](libs/shared/src/domain/utopia/doc-statements.test.ts#L233), [validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/doc-statements.test.ts#L86))
- FR2.7 — Each Section carries its heading as `text` beside its `title`, and the Document carries its first top-level (`# `) heading as `title`; a document with no top-level heading has no title. ([validated by builds one doc item with the repository, the Spec document and its three sections, duplicate headings deduped as chain and chain-2](libs/shared/src/domain/utopia/doc-statements.test.ts#L43), [validated by titles nothing for a document with no top-level heading, while its section still carries its heading as text](libs/shared/src/domain/utopia/doc-statements.test.ts#L241))
- FR2.8 — A statement's text past 4,000 characters is cut to its first 4,000 and an ellipsis, so one statement never pushes its item past the limits of FR2.5. ([validated by cuts a 5,003-character statement to its first 4,000 characters and an ellipsis](libs/shared/src/domain/utopia/doc-statements.test.ts#L256))
- FR2.9 — A statement split across items carries its text on the first item only; `.2`, `.3` and the rest repeat the Section and Statement entities without it. ([validated by keeps the text on the first of four split parts and on none of .2, .3 and .4](libs/shared/src/domain/utopia/doc-statements.test.ts#L263))

## The push

- FR3.1 — An item is posted to `POST /api/v1/sources/{source}/statements` under the source's own key, as `external_id`, `doc_time`, `e`, `s` and an empty `n`; the answer's `action` is returned. ([validated by posts the item under the source key with external_id, doc_time and an empty notes list, and returns the action](libs/shared/src/outbound/utopia/utopia-client.test.ts#L147))
- FR3.2 — A tombstone is `external_id` plus `deleted: true`, answered `marked_missing`. ([validated by posts a tombstone as external_id plus deleted true and returns marked_missing](libs/shared/src/outbound/utopia/utopia-client.test.ts#L173))
- FR3.3 — A 429 or 5xx is retried once after a short wait; a second failure, or any other refusal, throws a `UtopiaPushError` carrying the status and the first 300 characters of the body, with no retry. ([validated by retries once after a 503 and returns the second answer](libs/shared/src/outbound/utopia/utopia-client.test.ts#L188), [validated by gives up after two 503s with a UtopiaPushError carrying the status](libs/shared/src/outbound/utopia/utopia-client.test.ts#L201), [validated by throws a UtopiaPushError with the status and the first 300 body characters on a 422 without retrying](libs/shared/src/outbound/utopia/utopia-client.test.ts#L212))
- FR3.4 — A document's items are pushed four at a time; the outcome counts the items and how many Utopia created, updated and left unchanged, and names every item whose push threw while the rest still land. ([validated by pushes the doc item and one item per statement and counts created, updated and unchanged](libs/shared/src/work/utopia/mirror-document.test.ts#L41), [validated by names a statement item whose push threw under failed and still pushes the others](libs/shared/src/work/utopia/mirror-document.test.ts#L65))
- FR3.5 — A deleted document is tombstoned: its `doc:` item, and its statement items for the ordinals the caller knows; with none known, the `doc:` item alone. ([validated by tombstones the doc item and the statement items of the ordinals it is given](libs/shared/src/work/utopia/mirror-document.test.ts#L96), [validated by tombstones only the doc item when no ordinals are known](libs/shared/src/work/utopia/mirror-document.test.ts#L114))

## The ingest

- FR4.1 — The deployment reaches Utopia through `UTOPIA_API_URL` (`utopia.enabled` in the lore-api chart, from `enable_utopia`); without it the mirror is off. ([validated by is true with UTOPIA_API_URL set and false without it](libs/shared/src/outbound/utopia/utopia-client.test.ts#L121))
- FR4.2 — A repo is mirrored when its settings name a source in `utopia.source_id`, `lore.utopia_sources` holds the key of that same source, and the deployment has a Utopia; otherwise the ingest mirrors nothing. ([validated by pushes through the stored src-1 key when settings.utopia names src-1 and UTOPIA_API_URL is set](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L26), [validated by is null without UTOPIA_API_URL, without a utopia block, without a stored key, and with a key stored for another source](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L33))
- FR4.3 — After the delta route has projected a `specs` or `adrs` delta into the graph, each file is mirrored as a spec or an ADR at the delta's commit and each deleted path is tombstoned; a `code` delta mirrors nothing. ([validated by mirrors a projected spec as kind spec at the delta's commit and unmirrors the deleted one](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L164), [validated by mirrors nothing for a code delta](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L217))
- FR4.4 — A mirror that fails is logged as `[utopia-mirror] <repo> <path>: <message>`, counted on `lore_utopia_mirror_failures_total` by repo, and never fails the ingest, which answers 200 with what the graph did. ([validated by answers 200 with the projection counted when the mirror throws](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L191), [validated by counts a failed Utopia mirror of re-cinq/lore](libs/shared/src/outbound/otel/metrics.test.ts#L109))

## Setup

- FR5.1 — `POST /api/repos/{owner}/{repo}/utopia/setup` (admin scope) takes a person's Utopia session token and a workspace id. It finds the knowledge base named `owner/repo` in that workspace or creates it, imports the ontology, binds the ten kind words, creates a `statements` source named `lore`, saves the source's key to `lore.utopia_sources`, and writes `settings.utopia` with the knowledge base, the source and the ontology version. It answers the same three, never the key. ([validated by creates the knowledge base, imports the ontology, binds the ten kind words, creates the lore source, saves its key to lore.utopia_sources and its ids to settings](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L151), [validated by lists a workspace's knowledge bases under the session token](libs/shared/src/outbound/utopia/utopia-client.test.ts#L227), [validated by creates a knowledge base of kind knowledge with no ontology packs](libs/shared/src/outbound/utopia/utopia-client.test.ts#L248), [validated by imports the ontology as a multipart turtle file named lore-ontology.ttl](libs/shared/src/outbound/utopia/utopia-client.test.ts#L259), [validated by binds a kind word to its class key](libs/shared/src/outbound/utopia/utopia-client.test.ts#L279), [validated by creates a statements source and returns its id with the ingest token as the key](libs/shared/src/outbound/utopia/utopia-client.test.ts#L290))
- FR5.2 — A source is kept only when `lore.utopia_sources` holds its key for the knowledge base setup finds, since Utopia hands a source's key out once; a source the settings name without a stored key is replaced by a fresh one. ([validated by keeps the source whose key lore.utopia_sources holds for the knowledge base it finds by name](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L199), [validated by creates src-fresh when settings name src-old but lore.utopia_sources holds no key for it](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L217))
- FR5.3 — A repo Lore does not hold is a 404 before any call to Utopia; a deployment without `UTOPIA_API_URL` is a 503; a body without a session token is a 400. ([validated by answers 404 for a repo Lore does not hold and calls Utopia for nothing](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L227), [validated by answers 503 when UTOPIA_API_URL is unset](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L236), [validated by answers 400 without a session token](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L243))
- FR5.4 — The key never enters `lore.repos.settings`, which read-scope routes serve whole: it lives in `lore.utopia_sources`, one row per repo matched without regard to case, overwritten by each setup that creates a source, readable by the `lore` role alone and answered by no route. ([validated by leaves no source_key and no utp_ key anywhere in the settings it writes](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L187), [validated by reads the source saved for it-utopia/Lore back as it-utopia/lore, and a second save overwrites the key](apps/lore-api/src/integration-tests/utopia-sources.test.ts#L31), [validated by grants lore every privilege and lore_ui none](apps/lore-api/src/integration-tests/utopia-sources.test.ts#L50))

- FR5.5 — The setup calls carry any bearer Utopia accepts as a person: a session JWT or a personal access token with `write` scope (`utp_pat_…`, deeplethe/utopia#1244). The requests are the same; only the bearer differs. The route keeps taking a person's session token, for a deployment that holds no token of its own. ([validated by sends a utp_pat_1 write token as the bearer of the same request](libs/shared/src/outbound/utopia/utopia-client.test.ts#L238))

## Setup on first ingest

- FR6.1 — A deployment sets repos up itself when it has `UTOPIA_API_URL`, `UTOPIA_TOKEN` (the write token of the Utopia person Lore acts as, a workspace admin) and `UTOPIA_WORKSPACE_ID` (the workspace the bases are created in); missing any one, it does not. ([validated by is true with the URL, the token and the workspace id set, and false when any one of them is missing](libs/shared/src/outbound/utopia/utopia-client.test.ts#L130))
- FR6.2 — On such a deployment, the first spec or ADR ingest of a repo that FR4.2 would not mirror runs the setup of FR5.1 under that token in that workspace, saves the key to `lore.utopia_sources` and the ids to `settings.utopia` through the same writer the route uses, then mirrors the document to the new source. A repo already set up at the current ontology version is pushed to without calling Utopia (an older one is upgraded first, FR8.1), and a deployment without the token mirrors only repos a person set up. ([validated by sets re-cinq/lore up in ws-lore under the utp_pat_lore token on its first ingest, saves the key and the settings, and answers src-new](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L117), [validated by answers the stored src-1 without calling Utopia when settings already name it at ontology version 2](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L163), [validated by is null and calls Utopia for nothing on a deployment without UTOPIA_TOKEN](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L177))
- FR6.3 — Two ingests of one repo in one lore-api process share one setup: one knowledge base, one source, one saved key. Across processes, the knowledge base found by name and the one-row-per-repo upsert keep the repo at one base; a source created by each is possible, and the key saved last is the one pushed through. ([validated by shares one setup between two concurrent first ingests of re-cinq/lore: one knowledge base, one source, one saved key](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L142))
- FR6.4 — A failed setup is a failed mirror (FR4.4): logged, counted, never an ingest failure. Nothing is stored, and the next mirrored document of the repo tries the setup again. ([validated by rejects with Utopia's 403 and stores nothing when the knowledge base listing is refused, and the next ingest sets re-cinq/lore up](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L186))

## Ontology upgrade

A knowledge base keeps the ontology it was set up with until Lore imports a newer one. `settings.utopia.ontology_version` says which it holds; a setting without one reads as older than any version.

- FR8.1 — Before pushing a document of a repo whose stored `ontology_version` is below `LORE_ONTOLOGY_VERSION`, a deployment that can set repos up itself (FR6.1) imports the ontology into the repo's knowledge base under its token, binds every kind word, stores the new version in `settings.utopia`, and pushes. Two ingests of one repo in one process share one upgrade. ([validated by re-imports the ontology into kb-1 once for two concurrent ingests, binds the ten kind words, stores version 2, and answers src-1](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L235), [validated by answers the stored src-1 without calling Utopia when settings already name it at ontology version 2](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L163))
- FR8.2 — A deployment without a token pushes without upgrading and leaves the stored version as it is: the new attributes land in the base unbound to the ontology, still searchable. ([validated by answers src-1 and calls Utopia for nothing when the deployment has no UTOPIA_TOKEN, leaving version 1 stored](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L258))
- FR8.3 — A failed upgrade is logged as `[utopia-mirror] <repo> ontology upgrade: <message>` and counted as a failed mirror (FR4.4), the stored version stays, and the push goes ahead; the next ingest tries the upgrade again. ([validated by answers src-1 and counts one mirror failure for re-cinq/lore when Utopia refuses the import with 403, leaving version 1 stored](apps/lore-api/src/work/utopia/utopia-mirror.test.ts#L272))

## Backfill

A repo whose specs and ADRs were ingested before the mirror existed, or before it was set up, holds nothing in Utopia until each document changes again. The backfill pushes them all once.

- FR7.1 — The documents backfilled are the ones CI ingests (`isDocOfKind` in `apps/lore-code-trace/docs.go`): a `.md` file under `specs/` or `.specify/` is a spec and one under `adrs/` an ADR; a kind `.lore/ingest.yml` declares globs for takes the files those globs match instead. ([validated by selects specs/ and .specify/ markdown as spec and adrs/ markdown as adr without a manifest, skipping notes.txt, docs/ and README.md](apps/lore-api/src/work/utopia/utopia-backfill.test.ts#L20), [validated by selects only docs/managing-secrets.md as spec when .lore/ingest.yml declares a specs glob under docs, keeping the built-in adrs/ prefix](apps/lore-api/src/work/utopia/utopia-backfill.test.ts#L28))
- FR7.2 — Every such file is read at the head commit of the repo's default branch and mirrored through the ingest's mirror (FR3.4, FR4.2, FR6.2) as a spec or an ADR at that commit, two documents at a time. ([validated by mirrors the two specs and the ADR of main's head abc123 at abc123 and skips src/index.ts](apps/lore-api/src/work/utopia/utopia-backfill.test.ts#L55), [validated by reads heads/main of re-cinq/lore and answers its head sha abc123](libs/shared/src/outbound/project/lib/platform-github.test.ts#L796), [validated by answers the head sha of re-cinq/lore's main branch](libs/shared/src/outbound/project/repo/repo-files.test.ts#L62))
- FR7.3 — A document that throws, or one of whose items fails, is named under `failed` as `<path>: <message>` and the rest still go through. The created, updated and unchanged counts add up every document's items. ([validated by names specs/b/spec.md, which Utopia refused, and adrs/ADR-001-auth.md, one of whose items failed, under failed while specs/a/spec.md lands](apps/lore-api/src/work/utopia/utopia-backfill.test.ts#L103))
- FR7.4 — `POST /api/repos/{owner}/{repo}/utopia/backfill` (admin scope, no body) runs it and answers `commit`, `documents`, `created`, `updated`, `unchanged` and `failed`. ([validated by mirrors the spec and the ADR at main-head through the stored src-1 key and answers 2 documents and 4 created items, a doc and a statement each](apps/lore-api/src/transport/routes/repos/utopia-backfill.test.ts#L104))
- FR7.5 — A deployment without `UTOPIA_API_URL` is a 503 and a repo Lore does not hold a 404. A repo with no source, on a deployment that cannot set one up (FR6.1), is a 409 with `code: "utopia_not_set_up"` before any GitHub read: run the setup route first. ([validated by answers 409 utopia_not_set_up and reads nothing from GitHub when re-cinq/lore has no stored source and UTOPIA_TOKEN is unset](apps/lore-api/src/transport/routes/repos/utopia-backfill.test.ts#L123), [validated by answers 404 for a repo Lore does not hold](apps/lore-api/src/transport/routes/repos/utopia-backfill.test.ts#L139), [validated by answers 503 when UTOPIA_API_URL is unset](apps/lore-api/src/transport/routes/repos/utopia-backfill.test.ts#L145))
- FR7.6 — `scripts/infra/utopia-backfill.sh` backfills every onboarded repo: it pages through `GET /api/repos` and posts the route for each `full_name`, with `LORE_API_URL` and an admin-scope `LORE_ADMIN_TOKEN` from the environment. A 409 repo is skipped; any other refusal, or any document under `failed`, exits 1. Re-running it is safe, since a document Utopia already holds comes back unchanged.

  ```bash
  LORE_API_URL=https://<lore-api host> LORE_ADMIN_TOKEN=<admin token> scripts/infra/utopia-backfill.sh
  ```

## Weekly backfill

A mirror that failed, or a repo set up after its documents were ingested, would wait for the next change to each document. The stations service runs the backfill every Sunday instead, so the mirror heals within the week without anyone running the script. A push still mirrors what it changes at once; the weekly run only catches what a push missed.

- FR7.7 — The `cron.utopia_backfill.tick` fires weekly, Sundays at 02:30 UTC, and the `utopia-backfill-tick` sweep in the stations service answers it. ([validated by schedules utopia_backfill weekly on Sunday at 02:30 UTC](libs/shared/src/work/scheduler/cron-emitters.test.ts#L39))
- FR7.8 — The sweep posts lore-api's backfill route (FR7.4) for every onboarded repo in name order, one repo at a time, so a slow Utopia carries one repo's documents at once. ([validated by backfills re-cinq/lore then re-cinq/floor in order and reports both done](apps/stations/src/work/utopia-backfill-tick/utopia-backfill-tick.test.ts#L40))
- FR7.9 — Each call presents the stations' lore-api token (`LORE_STATION_TOKEN`, lore-api's own `LORE_INGEST_TOKEN`, which carries every scope the admin-only route asks for) and waits up to 30 minutes for the answer; a call with no answer by then is that repo's failure. ([validated by posts re-cinq/lore's backfill with the station token and answers lore-api's 409 status and body whole](apps/stations/src/work/utopia-backfill-tick/lore-api-backfill.test.ts#L53), [validated by rejects with no answer within 50ms when lore-api holds the call past the timeout](apps/stations/src/work/utopia-backfill-tick/lore-api-backfill.test.ts#L71))
- FR7.10 — The tick's delivery is held for 12 hours, not the bus's 10 minutes, so the reaper does not hand a night of backfills to a second run while the first is still going. ([validated by claims cron.utopia_backfill.tick with a 43200-second visibility budget, so the reaper leaves a night of one-repo-at-a-time backfills running](apps/stations/src/events/subscriptions.test.ts#L99))
- FR7.11 — A repo answered 409 `utopia_not_set_up` is skipped. A repo answered with any other refusal, whose call threw, or with a document under `failed` is logged and counted as failed, and the next repo still runs. The sweep's summary names the repos done, skipped and failed. ([validated by skips re-cinq/otto, which answers 409 utopia_not_set_up, and still backfills re-cinq/lore](apps/stations/src/work/utopia-backfill-tick/utopia-backfill-tick.test.ts#L58), [validated by logs re-cinq/otto's 500, re-cinq/hal's refused document and re-cinq/ui's dropped socket as failed, and still backfills re-cinq/lore after them](apps/stations/src/work/utopia-backfill-tick/utopia-backfill-tick.test.ts#L72), [validated by counts re-cinq/otto's 200 with an unreadable body as failed and still backfills re-cinq/lore](apps/stations/src/work/utopia-backfill-tick/utopia-backfill-tick.test.ts#L107))
- FR7.12 — A 503 means the deployment has no Utopia: the sweep stops there and asks for no other repo. ([validated by stops at the first 503 and asks for no other repo, since this deployment has no Utopia](apps/stations/src/work/utopia-backfill-tick/utopia-backfill-tick.test.ts#L97))

## Out of scope

- Reading the mirror: the spec pages, the detectors and `query_trace` keep reading Dgraph.
- Tests and code definitions from the test and code ingests; the ontology declares them (`covers`, `defines`, `references`, `imports`) for the slice that pushes them.
- Tombstoning the statement items of a deleted document; the ordinals of the last push are not stored yet.
- The text of code: a source file is named and linked by path, and its contents are not copied into Utopia.
