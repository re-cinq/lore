Every spec, ADR and other markdown document lore-api ingests is also written into Utopia, the knowledge-graph service deployed beside Lore, as the chain it draws from the document: the document, its sections, their statements, and the tests, source files and ADRs each statement links. ADR-052 records why.

## Background

Dgraph holds the traceability graph today and is to be retired. Utopia already runs in the cluster and keeps a typed graph, but it cannot yet answer two of the reads Lore's checks make, so the chain is mirrored there beside Dgraph rather than moved. The mirror is a copy: nothing in Lore reads it yet, and its failure never fails an ingest.

## The ontology

- FR1.1 — The Lore ontology is one turtle file, `libs/shared/src/domain/lore-ontology.ttl`, read beside the module that names it and copied beside `dist` by the build. Its eighteen classes are the kind words a pushed entity carries, each bound in Utopia to the snake_case key of its label. - FR1.2 — `LORE_ONTOLOGY_VERSION` is stored with the repo's settings at setup; a change to the turtle's shape bumps it.
- FR1.3 — Version 2 declares the `text` attribute, a string on Section and Statement, and adds Document to the domain of `title`, so the words a statement says and the title of its document are attributes the base knows. ([validated by declares text on Section, Statement, Commit, PullRequest, Issue and Release and title on Document, Commit, PullRequest, Issue and Release, both strings, so a pushed statement's words, a pull request's body and a document's title are attributes the base knows @79fa1667](libs/shared/src/domain/lore-ontology.test.ts#L49))
- FR1.4 — Version 3 declares what a test run says: `violated_by` from Statement to Test, `outcome` a string on Test, Test in the domain of `commit`, and a SourceFile `contains` its Tests; `covers` names its `lines` and `commit` qualifiers. It adds no class. ([validated by declares violated_by from Statement to Test, outcome as a string on Test, Test under commit, and SourceFile containing Test, so a test run's statements are terms the base knows @d5f055cb](libs/shared/src/domain/lore-ontology.test.ts#L66))
- FR1.5 — Version 6 declares Lore's classes pairwise `owl:disjointWith`, the form Utopia's importer reads, at the highest class each holds for: Repository, Document, Section, Statement, Test, Code, the four history classes, Release, Tag and Person against one another, Spec against Adr and SourceFile against CodeDefinition. - FR1.6 — Version 8 declares `Person`, a class disjoint from every other, and `authored_by` (Commit, PullRequest, Issue → Person, an event), so who wrote a commit or opened a pull request is a relation the base knows. - FR1.7 — Version 9 declares `anchor_hash`, a string on Test: the content hash of the test's declaration line, which names the test a hashed spec link cites. ([validated by reads the turtle file beside the module, which declares every kind word as a class at version 10 @330d8170](libs/shared/src/domain/lore-ontology.test.ts#L37), [validated by returns anchor_hash a3f9c1d2 for a test whose descriptor carries it, and none for one that does not @e757ea33](libs/shared/src/domain/utopia/test-coverage/test-report-statements.test.ts#L166))
- FR1.8 — Version 10 declares what a file's structure says: `kind` (class, method, function, interface, type or enum) and `exported` on CodeDefinition, `extends` and `implements` between definitions, a CodeDefinition that `contains` its methods, `anchor_hash` on CodeDefinition as on Test, and `implemented_by` reaching a CodeDefinition. ## Names

Utopia resolves an entity by its lower-cased name and flags a name that is a substring of another same-class name, so every name carries the repository and the path:

- repository `owner/repo`; document `owner/repo:<path>`; section `owner/repo:<path>#<heading-slug>`, with a repeated heading suffixed `-2`, `-3` in order; statement `owner/repo:<path>#s<ordinal, four digits>`; test `owner/repo:<test path>::<test title>`; source file `owner/repo:<path>`; an ADR a statement links is the same name its own document has. One module (`libs/shared/src/domain/utopia/names.ts`) builds them for every item, so a test run names a test and the statement it validates exactly as a document's links do; a test's title is the one written in its `it()` call, without the describe chain a runner may prefix. ([validated by names the statement and test exactly as the doc mirror names them @d73d0416](libs/shared/src/domain/utopia/test-coverage/test-report-statements.test.ts#L307))

## The words

Utopia's search and chat read what an item says: the pushed statements become the chunk it searches and cites, attribute values included. An item holding only names, ids, lines and permalinks gives a question about a spec nothing to answer from, so the prose of specs and ADRs is copied into the items. Code stays linked by path and is never copied.

- FR2.6 — Each Statement carries `text`: its words as written, with the coverage-link parentheticals stripped (`stripCoverageLinks`, the same grammar search uses) and every run of whitespace collapsed to one space. ([validated by gives the statement the text FR1 — Spaced words. with its coverage links stripped and its runs of spaces collapsed @692018c8](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L210), [validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file @678a289f](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L48))
- FR2.8 — A statement's text past 4,000 characters is cut to its first 4,000 and an ellipsis, so one statement never pushes its item past the limits of FR2.5. ([validated by cuts a 5,003-character statement to its first 4,000 characters and an ellipsis @d43ef86a](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L222))
- FR2.9 — A statement split across items carries its text on the first item only; `.2`, `.3` and the rest repeat the Section and Statement entities without it. ([validated by keeps the text on the first of three split parts and on none of .2 and .3 @5b730a0b](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L225))

## Setup

- FR5.1 — `POST /api/repos/{owner}/{repo}/utopia/setup` (admin scope) takes a person's Utopia session token and a workspace id. ## Out of scope

- Reading the mirror: the spec pages, the detectors and `query_trace` keep reading Dgraph, and only the `repo` and `adrs` sections of context assembly read through the client of FR11 (FR13).
- Statement items orphaned before migration 0123: their document has no recorded ids, so nothing tombstones them.
- The text of code: a source file and its definitions are named and linked by their GitHub permalinks, and their contents are not copied into Utopia. Documents are the other way round: every markdown document goes in whole (FR17).
- The files a commit changed, and what it changed inside them: they are read from the repository.
- Commits on any branch but the default one, and the history of a pull request's own commits: a squash merge is one commit.
- A pull request's reviews, its review comments and the conversation on an issue or a pull request: the tracker mirror holds what an issue or a pull request says of itself.
- Tombstoning a deleted issue, release or tag: GitHub's lists no longer return it, so its item stays as it last was.
- Reading memory from Utopia.
- Lore's own fact handling in Utopia: Lore retires a fact that a new one contradicts at 0.92 similarity, where Utopia closes or reviews the contradiction itself, so a later read of Utopia's facts will not match Lore's one for one.
