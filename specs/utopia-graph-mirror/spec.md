Every spec, ADR and other markdown document lore-api ingests is also written into Utopia, the knowledge-graph service deployed beside Lore, as the chain it draws from the document: the document, its sections, their statements, and the tests, source files and ADRs each statement links. ADR-052 records why.

## Background

Dgraph holds the traceability graph today and is to be retired. Utopia already runs in the cluster and keeps a typed graph, but it cannot yet answer two of the reads Lore's checks make, so the chain is mirrored there beside Dgraph rather than moved. The mirror is a copy: nothing in Lore reads it yet, and its failure never fails an ingest.

## The ontology

- FR1.1 — The Lore ontology is one turtle file, `libs/shared/src/domain/lore-ontology.ttl`, read beside the module that names it and copied beside `dist` by the build. Its seventeen classes are the kind words a pushed entity carries, each bound in Utopia to the snake_case key of its label. ([validated by binds the seventeen class labels of the chain and its history to their snake_case class keys](libs/shared/src/domain/lore-ontology.test.ts#L9), [validated by reads the turtle file beside the module, which declares every kind word as a class at version 7](libs/shared/src/domain/lore-ontology.test.ts#L36))
- FR1.2 — `LORE_ONTOLOGY_VERSION` is stored with the repo's settings at setup; a change to the turtle's shape bumps it.
- FR1.3 — Version 2 declares the `text` attribute, a string on Section and Statement, and adds Document to the domain of `title`, so the words a statement says and the title of its document are attributes the base knows. ([validated by declares text on Section, Statement, Commit, PullRequest, Issue and Release and title on Document, Commit, PullRequest, Issue and Release, both strings, so a pushed statement's words, a pull request's body and a document's title are attributes the base knows](libs/shared/src/domain/lore-ontology.test.ts#L48))
- FR1.4 — Version 3 declares what a test run says: `violated_by` from Statement to Test, `outcome` a string on Test, Test in the domain of `commit`, and a SourceFile `contains` its Tests; `covers` names its `lines` and `commit` qualifiers. It adds no class. ([validated by declares violated_by from Statement to Test, outcome as a string on Test, Test under commit, and SourceFile containing Test, so a test run's statements are terms the base knows](libs/shared/src/domain/lore-ontology.test.ts#L65))
- FR1.5 — Version 6 declares Lore's classes pairwise `owl:disjointWith`, the form Utopia's importer reads, at the highest class each holds for: Repository, Document, Section, Statement, Test, Code, the four history classes, Release and Tag against one another, Spec against Adr and SourceFile against CodeDefinition. Utopia inherits a declaration down `rdfs:subClassOf`, so every two of the fourteen leaf classes are disjoint, and its containment and type-drift duplicate proposals skip such a pair: a Spec and its Statement, or a SourceFile and its CodeDefinition, whose names contain each other, are never proposed as one entity. ([validated by declares every pair of Lore's leaf classes disjoint, so Utopia never proposes a Spec and its Statement as one entity](libs/shared/src/domain/lore-ontology.test.ts#L195))

## Names

Utopia resolves an entity by its lower-cased name and flags a name that is a substring of another same-class name, so every name carries the repository and the path:

- repository `owner/repo`; document `owner/repo:<path>`; section `owner/repo:<path>#<heading-slug>`, with a repeated heading suffixed `-2`, `-3` in order; statement `owner/repo:<path>#s<ordinal, four digits>`; test `owner/repo:<test path>::<test title>`; source file `owner/repo:<path>`; an ADR a statement links is the same name its own document has. One module (`libs/shared/src/domain/utopia/names.ts`) builds them for every item, so a test run names a test and the statement it validates exactly as a document's links do; a test's title is the one written in its `it()` call, without the describe chain a runner may prefix. ([validated by names the statement and test exactly as the doc mirror names them](libs/shared/src/domain/utopia/test-coverage/test-report-statements.test.ts#L239))

## The items

*(2026-10-22)* The `doc:<path>` statement item with its Document and Section entities, which FR2.1 and FR2.7 described until this date, is no longer built or pushed: the document travels as text (FR18.7), and only its statements are items (FR2.2, FR18.8).

- FR2.2 — Each statement becomes one `stmt:<path>#<ordinal>` item, pushed to the `test-coverage` source (FR18.8): its Section `contains` the Statement (a bare Section entity named for the heading, the document itself being text); the Statement's `line_start`, `permalink` with `#L<line>` and `text` (FR2.6); for every test link, Statement `validated_by` Test with the Test's `title` (FR2.10), `path`, `line_start` when the link carries a line anchor, and `permalink`; for every code link, Statement `implemented_by` SourceFile with its `path`. ([validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L47))
- FR2.3 — A link to a file under `adrs/` is not a code link; it makes the Statement `decided_by` that Adr. ([validated by links a statement to an ADR with decided_by and treats the ADR as no code link](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L107))
- FR2.4 — A statement sits under the last heading before its line, so the second of two same-named sections holds its own statements. A statement written before the first heading sits directly under the document's own entity, never under a second one of the same name. Every item carries `doc_time` when the commit's time is known and no `doc_time` otherwise. ([validated by files the sentence under the second chain section as chain-2 and omits doc_time for an undated commit](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L134), [validated by files a README's first sentence under its Usage section](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L147), [validated by files a statement written before any heading under the Adr document, never a second Document of the same name](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L165))
- FR2.5 — An item never exceeds 200 statements or 60 KiB. A statement with more links than fit is split: the first item keeps its id and the rest take `.2`, `.3`, every one repeating the Section and Statement entities. ([validated by splits a statement with 80 test links into four items under 200 statements each that repeat the section and statement entities](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L179))
- FR2.10 — A test link names its Test by the title written in the test's `it()` call, the name a test run gives the same test (FR9.2): the link label after "validated by", without the backticks around it. A label that gives no title (empty, or a `file.test.ts:21` that says where a test once stood) is resolved instead from the test file read at the commit: the title is the last `it`/`test` declared at or above the link's line anchor. A link whose title neither its label nor its source gives links no Test, so no Test is ever named by a file and line. ([validated by names the test behind a context-freshness.test.ts:21 label by the title declared at its #L6 anchor, and a backticked title without its backticks](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L270), [validated by links no test for an empty label or a gone.test.ts:9 label whose source was not read](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L285), [validated by returns the title declared on line 4 when the anchor is line 4](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L34), [validated by returns the enclosing test's title when the anchor is line 9 inside its body](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L40), [validated by returns null when the anchor is line 3, above every test](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L44), [validated by returns the it and test.skip titles with their lines 4 and 8, template placeholders as written](libs/shared/src/domain/spec-trace/test-declarations.test.ts#L22))
- FR2.11 — The mirror reads only the test files whose links' labels give no title, once each, at the document's commit, from the repo's GitHub contents; a file it cannot read gives its links no title. ([validated by returns the context-freshness, other and gone test paths, whose labels name no title, once each](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L293), [validated by reads src/a.test.ts and src/gone.test.ts at the commit and names the a.test.ts:3 link by its it title, linking nothing for the file that is gone](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L137))

## The words

Utopia's search and chat read what an item says: the pushed statements become the chunk it searches and cites, attribute values included. An item holding only names, ids, lines and permalinks gives a question about a spec nothing to answer from, so the prose of specs and ADRs is copied into the items. Code stays linked by path and is never copied.

- FR2.6 — Each Statement carries `text`: its words as written, with the coverage-link parentheticals stripped (`stripCoverageLinks`, the same grammar search uses) and every run of whitespace collapsed to one space. ([validated by gives the statement the text FR1 — Spaced words. with its coverage links stripped and its runs of spaces collapsed](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L210), [validated by builds a statement item with two validated_by tests, titles taken after validated by, and one implemented_by source file](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L47))
- FR2.8 — A statement's text past 4,000 characters is cut to its first 4,000 and an ellipsis, so one statement never pushes its item past the limits of FR2.5. ([validated by cuts a 5,003-character statement to its first 4,000 characters and an ellipsis](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L222))
- FR2.9 — A statement split across items carries its text on the first item only; `.2`, `.3` and the rest repeat the Section and Statement entities without it. ([validated by keeps the text on the first of four split parts and on none of .2, .3 and .4](libs/shared/src/domain/utopia/docs/doc-statements.test.ts#L225))

## The push

- FR3.1 — An item is posted to `POST /api/v1/sources/{source}/statements` under the source's own key, as `external_id`, `doc_time`, `e`, `s` and an empty `n`; the answer's `action` is returned. ([validated by posts the item under the source key with external_id, doc_time and an empty notes list, and returns the action](libs/shared/src/outbound/utopia/utopia-client.test.ts#L180))
- FR3.2 — A tombstone is `external_id` plus `deleted: true`, answered `marked_missing`. ([validated by posts a tombstone as external_id plus deleted true and returns marked_missing](libs/shared/src/outbound/utopia/utopia-client.test.ts#L206), [validated by counts nothing for a tombstone Utopia marked missing](libs/shared/src/work/utopia/push-items.test.ts#L57))
- FR3.3 — A 429 or 5xx is retried once after a short wait; a second failure, or any other refusal, throws a `UtopiaError` carrying the status and the first 300 characters of the body, with no retry. ([validated by retries once after a 503 and returns the second answer](libs/shared/src/outbound/utopia/utopia-client.test.ts#L221), [validated by gives up after two 503s with a UtopiaError carrying the status](libs/shared/src/outbound/utopia/utopia-client.test.ts#L234), [validated by throws a UtopiaError with the status and the first 300 body characters on a 422 without retrying](libs/shared/src/outbound/utopia/utopia-client.test.ts#L245))
- FR3.4 — A document's items are pushed four at a time; the outcome counts the items and how many Utopia created, updated and left unchanged, and names every item whose push threw while the rest still land, an item Utopia answers `duplicate` (another document in the knowledge base holds the same content) among them, counted under none of the three. ([validated by counts doc:a created, doc:b updated and doc:c unchanged and names nothing under failed](libs/shared/src/work/utopia/push-items.test.ts#L21), [validated by names test:a.ts under failed and counts no NaN when Utopia answers duplicate](libs/shared/src/work/utopia/push-items.test.ts#L40), [validated by pushes doc:specs/mirror/spec.md whole to the text source and one stmt item per statement to the statements source, counting created, updated and unchanged](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L60), [validated by names a statement item whose push threw under failed, still pushes the others and the text](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L88))
- FR3.5 — A deleted document is tombstoned in the `docs` source: its `doc:<path>` text document, as `external_id`, `filename` and `deleted: true`. Its `stmt:` items in the `test-coverage` source stay until a later push of the file replaces them. ([validated by tombstones doc:adrs/ADR-1.md in the text source and leaves the statements alone](libs/shared/src/work/utopia/docs/mirror-document.test.ts#L174), [validated by is doc:adrs/ADR-1.md deleted, named after its path](libs/shared/src/domain/utopia/docs/doc-text.test.ts#L36), [validated by posts the doc:adrs/ADR-1.md tombstone to the docs source and nothing to test-coverage](apps/lore-api/src/work/utopia/docs/mirror-doc.test.ts#L165))

## The ingest

- FR4.1 — The deployment reaches Utopia through `UTOPIA_API_URL` (`utopia.enabled` in the lore-api chart, from `enable_utopia`); without it the mirror is off. ([validated by is true with UTOPIA_API_URL set and false without it](libs/shared/src/outbound/utopia/utopia-client.test.ts#L126))
- FR4.2 — A repo is mirrored when its settings name its knowledge base in `utopia.kb_id` and the deployment has a Utopia; otherwise the ingest mirrors nothing. Documents, test runs, code, commits, issues, releases and memories are pushed to the sources of FR18 and FR16 in that base. *(2026-10-23: the gate was a `lore` source named in `utopia.source_id` whose key `lore.utopia_sources` held; migration 0119 drops `source_id` from every repo's settings.)* ([validated by answers kb-1 without calling Utopia or writing when settings.utopia names kb-1 at ontology version 7](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L94), [validated by is null without UTOPIA_API_URL, and without a utopia block on a deployment without UTOPIA_TOKEN](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L105))
- FR4.3 — After the delta route has projected a `specs` or `adrs` delta into the graph, each file is mirrored as a spec or an ADR at the delta's commit and each deleted path is tombstoned. A default-branch `test-report` delta mirrors its tests (FR9) and a `code` delta its source files (FR10); a branch's report mirrors nothing. ([validated by mirrors a main test-report at the delta's commit after projecting it](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L365), [validated by mirrors nothing for a feat/x test-report delta](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L830), [validated by mirrors a projected spec as kind spec at the delta's commit and unmirrors the deleted one](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L186), [validated by mirrors a main code delta's files after projecting them](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L239))
- FR4.4 — A mirror that fails is logged as `[utopia-mirror] <repo> <path>: <message>`, counted on `lore_utopia_mirror_failures_total` by repo, and never fails the ingest, which answers 200 with what the graph did. ([validated by answers 200 with test_chunks counted when the report mirror throws](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L405), [validated by answers 200 with the projection counted when the mirror throws](apps/lore-api/src/transport/routes/ingest/ingest-delta.test.ts#L213), [validated by counts a failed Utopia mirror of re-cinq/lore](libs/shared/src/outbound/otel/metrics.test.ts#L122))

## Setup

- FR5.1 — `POST /api/repos/{owner}/{repo}/utopia/setup` (admin scope) takes a person's Utopia session token and a workspace id. It answers those two. It creates no source: each source is made the first time something of its kind is pushed (FR18.1, FR16.4). *(2026-10-23: setup used to create a `statements` source named `lore` and keep its key in `lore.utopia_sources`.)* ([validated by creates the knowledge base, imports the ontology, binds the seventeen kind words, creates no source, and saves kb-new to lore.utopia_bases and settings](apps/lore-api/src/transport/routes/repos/utopia-setup.test.ts#L130), [validated by lists a workspace's knowledge bases under the session token](libs/shared/src/outbound/utopia/utopia-client.test.ts#L260), [validated by creates a knowledge base of kind knowledge with no ontology packs](libs/shared/src/outbound/utopia/utopia-client.test.ts#L281), [validated by imports the ontology as a multipart turtle file named lore-ontology.ttl](libs/shared/src/outbound/utopia/utopia-client.test.ts#L292), [validated by binds a kind word to its class key](libs/shared/src/outbound/utopia/utopia-client.test.ts#L340), [validated by creates a statements source and returns its id with the ingest token as the key](libs/shared/src/outbound/utopia/utopia-client.test.ts#L351))

## Ontology upgrade

A knowledge base keeps the ontology it was set up with until Lore imports a newer one. `settings.utopia.ontology_version` says which it holds; a setting without one reads as older than any version.

- FR8.1 — Before pushing a document of a repo whose stored `ontology_version` is below `LORE_ONTOLOGY_VERSION`, a deployment that can set repos up itself (FR6.1) imports the ontology into the repo's knowledge base under its token, binds every kind word, stores the new version in `settings.utopia`, and pushes. Two ingests of one repo in one process share one upgrade. ([validated by re-imports the ontology into kb-1 once for two concurrent ingests, binds the seventeen kind words, stores version 7, and answers kb-1](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L194), [validated by answers kb-1 without calling Utopia or writing when settings.utopia names kb-1 at ontology version 7](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L94))
- FR8.2 — A deployment without a token pushes without upgrading and leaves the stored version as it is: the new attributes land in the base unbound to the ontology, still searchable. ([validated by answers kb-1 and calls Utopia for nothing when the deployment has no UTOPIA_TOKEN, leaving version 1 stored](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L214))
- FR8.3 — A failed upgrade is logged as `[utopia-mirror] <repo> ontology upgrade: <message>` and counted as a failed mirror (FR4.4), the stored version stays, and the push goes ahead; the next ingest tries the upgrade again. ([validated by answers kb-1 and counts one mirror failure for re-cinq/lore when Utopia refuses the import with 403, leaving version 1 stored](apps/lore-api/src/work/utopia/repo-mirror.test.ts#L228))
- FR8.4 — An ontology import waits up to five minutes for Utopia's answer, a push or a read 30 seconds. An import plans against the whole base, writes every class and relation and queues alignment, so on a busy base it outlasts a push's wait: with one timeout for both, the version-4 upgrade timed out on every ingest on 2026-10-17 while the base's database sat at its CPU limit. ([validated by waits past the 50ms request timeout for an import Utopia answers after 200ms, while a push that slow is aborted](libs/shared/src/outbound/utopia/utopia-client.test.ts#L312))

## Backfill

## Weekly backfill

## Commits

The chain says what a repository's documents, tests and code are; the default branch's commits say when each changed, by which pull request, for which issue or Lore task. `commitDocument` (`libs/shared/src/domain/utopia/git-history/commit-text.ts`) turns one commit into a text document for the `git-history` source, lore-api walks the branch above a cursor (`apps/lore-api/src/work/utopia/git-history/utopia-commits.ts`), and the stations post that walk on every push.

*(2026-10-22)* A commit is pushed as the standard text of the commit, not as statements: who made it, when, on top of which commits, its page, then the message whole. It never names the files it changed. Each changed path would be an entity Utopia resolves against the whole base, and a commit touching forty files named forty of them: on 2026-10-17, with Utopia's queue growing, the file list was dropped. Which files a commit or its pull request changed, and what it changed inside them, is read from the repository.

## Starting over

*(2026-10-22)* A base filled through the one `lore` source holds the statement, test and code items `test-coverage` takes, and Utopia refuses a second copy (FR18.6). Emptying that source is a delete and a purge per document, each a pass over the whole base's facts: about 10 seconds a document, one after another, so a base of tens of thousands takes days and keeps the database saturated. ## Out of scope

- Reading the mirror: the spec pages, the detectors and `query_trace` keep reading Dgraph, and only the `repo` and `adrs` sections of context assembly read through the client of FR11 (FR13).
- Tombstoning the statement items of a deleted document; the ordinals of the last push are not stored yet.
- The text of code: a source file and its definitions are named and linked by their GitHub permalinks, and their contents are not copied into Utopia. Documents are the other way round: every markdown document goes in whole (FR17).
- The files a commit changed, and what it changed inside them: they are read from the repository.
- Commits on any branch but the default one, and the history of a pull request's own commits: a squash merge is one commit.
- A pull request's reviews, its review comments and the conversation on an issue or a pull request: the tracker mirror holds what an issue or a pull request says of itself.
- Tombstoning a deleted issue, release or tag: GitHub's lists no longer return it, so its item stays as it last was.
- Reading memory from Utopia.
- Lore's own fact handling in Utopia: Lore retires a fact that a new one contradicts at 0.92 similarity, where Utopia closes or reviews the contradiction itself, so a later read of Utopia's facts will not match Lore's one for one.
