# Feature Specification: Context evals

| Field   | Value                                                                 |
| ------- | --------------------------------------------------------------------- |
| Feature | Context evals                                                         |
| Status  | In Progress                                                           |
| Created | 2026-10-02                                                            |
| Owner   | Platform Engineering                                                  |
| Module  | `scripts/context-evals/`, `apps/lore-api/src/work/context-evals/`, `apps/lore-api/src/transport/routes/context-evals/` |

A context eval asks one thing of Lore: when a developer asks about something a document decides, does Lore hand that document back, and can the question be answered from what it handed back. The questions are written from the documents themselves, so nobody writes or maintains a suite.

## Background

Lore's job is to give an agent the right documents for its question, and nothing measured whether it did. From 2026-08-13 to 2026-09-09 every embedding call was refused and every assembled context opened with the same three chunks, whatever the question; it was found by accident four weeks in (#1922 to #1937). The two nightly jobs meant to catch this, `eval_runner` and `context_core_builder`, never ran a suite and were deleted with Lore's own Floor on 2026-10-02, and the `evals` CI check skipped on every pull request for want of a model key, over suites that asked about a fictional company.

A hand trial on 2026-10-02 (five ADR questions against production) found the right ADR every time, and found a third to a half of each 8,000-token context spent on unrelated documents (#2459). A check that only asks whether the document came back would have read green. So an eval reports three things: found, answered, and the share of the returned tokens that was used. The first all-repository run (2026-10-02) showed what each is worth as a gate: four documents were answered correctly from other documents without being returned themselves, and four answers were failed for detail their document does not mention. Since then a repository is gated on `answered` alone, and a contradiction has to be quoted from the document.

The evals are run from a developer machine, not on a schedule, in CI, or in the cluster (2026-10-19: they are experiments a person runs and writes up, and an unattended nightly run had gone red three nights running on one document nobody read). The runner samples, asks and reports, and lore-api does the part that must be the code path an agent gets. The runner holds the token it already uses for ingest and no model key.

## One document's eval

- FR1.1 — `evaluateDocument` evaluates one document of one repository and reports its path, the question asked, `found`, `answered`, `useful_share`, the judge's one-sentence `reason`, the model that ran, and `sources`: each returned source's path, section, tokens and whether the answer used it, so a low useful share can be traced to the section its unused tokens came from. ([validated by reports ADR-032 found, answered and a useful share of 0.6 when 600 of 1000 returned tokens come from the sources the answer used @c3d20fde](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L63))
- FR1.2 — The question is written by the model from the document, and is the question Lore is asked for that document's repository. It stands on its own: it names the tool, route or rule it asks about and never the document, so it reads as a developer's question would. ([validated by asks Lore the question the model wrote, for the document's repository @5b4b2b77](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L92))
- FR1.3 — `found` is true when the document's own path is among the sources Lore returned. ([validated by reports found false when ADR-032 is not among the returned sources @7c8041db](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L100))
- FR1.4 — `answered` says whether the answer the model gave from the returned context only stands against the document. The judge reports whether the answer addresses the question and, when it contradicts the document, the sentence of the document it contradicts, word for word; the pass is decided in code. An answer fails when it does not address the question (saying the context did not hold the answer counts as that) or when the quoted sentence is in the document, compared without regard to case, line breaks or spacing. Nor does it fail when the judge says the quoted sentence and the answer can both hold, as a default and a startup check do. A claimed contradiction whose sentence is not in the document is not one: the answer is drawn from everything Lore returned, and correct detail the document does not mention has no sentence to quote. A failed answer carries the judge's reason. ([validated by reports answered false when the judge quotes a sentence of the document the answer contradicts @5886d97f](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L121), [validated by reports answered true when the judge quotes a sentence but says it and the answer can both hold @dfb626b3](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L136), [validated by reports answered true when the sentence the judge calls contradicted is not in the document @c4f2ec56](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L170), [validated by finds the quoted sentence in the document whatever its line breaks and spacing @b0e93ed2](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L183), [validated by reports answered false when the judge says the answer does not address the question @e9e637b4](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L194))
- FR1.5 — `useful_share` is the tokens of the returned sources the answer named as used, over all tokens returned, to two decimals. A source the answer names that Lore did not return counts for nothing. ([validated by counts only sources Lore returned towards the useful share, whatever else the answer names @d6e1afc0](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L225))
- FR1.6 — When Lore returns no context, the document is reported not found and not answered with the reason "Lore returned no context for the question", and no answer or verdict is asked of the model. ([validated by asks for no answer and no verdict when Lore returns no context @9aae61d7](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L235))
- FR1.7 — A document Lore does not hold evaluates to nothing and costs no model call. ([validated by returns null and calls no model for a document Lore does not hold @fa9beacf](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L247))
- FR1.8 — Every model call carries the job name `context-evals`, which is what files its cost under that name in `pipeline.llm_calls`. ([validated by tags all three model calls with the job name context-evals @a56f6463](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L254))
- FR1.8a — All three model calls are made at temperature 0, so a rerun of the same question differs as little as the model allows. Measured on 113 pinned questions run twice: five verdicts differed. ([validated by asks the model for all three calls at temperature 0, so a rerun of the same question differs as little as the model allows @0097976d](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L162))
- FR1.8b — The verdict may be asked of a stronger model than the one that writes the question and answers: `judgeModel` names it for the judging call alone (`LORE_EVAL_JUDGE_MODEL`; the chart leaves it unset, since `gemini-2.5-pro` judged a full run on 2026-10-03 and changed no repository's verdict), and the other two calls keep the provider's default. ([validated by asks the judge model gemini-2.5-pro for the verdict alone, and the default model for the question and the answer @e5620080](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L150))
- FR1.9 — The model is shown at most 12,000 characters of a document. ([validated by shows the model at most 12000 characters of a longer document @8163e81c](apps/lore-api/src/work/context-evals/evaluate-document.test.ts#L266))

## The documents

- FR2.1 — A repository's eval documents are its ingested ADRs and `spec.md` files, read from the chunks an agent's context is assembled from, in the repository's own chunk schema. ([validated by reads the first chunk of every ADR and spec.md of re-cinq/lore from org_shared and returns the live ones @a1673d77](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L59))
- FR2.2 — A document whose status says it is retired, rejected, superseded or deprecated is left out; a document that states no status is kept. ([validated by keeps a Shipped spec and an accepted ADR @743840c1](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L32), [validated by drops a Retired spec, a Rejected spec and a superseded ADR @3992a83e](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L41), [validated by keeps a document that states no status @52b6831b](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L51))
- FR2.3 — A document's text is its chunks joined in order, and a path with no ADR or spec chunks has no text. ([validated by joins the chunks of adrs/ADR-007.md in order @cf4e9b4b](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L78), [validated by returns null for a path with no ADR or spec chunks @fac9156a](apps/lore-api/src/work/context-evals/eval-documents.test.ts#L93))

## What Lore is asked

- FR3.1 — The context is assembled by the function `GET /api/context` uses, with the default template and budget, so an eval measures what an agent gets. The returned sources are every item of every section the budget kept, each with its path, its section and its tokens; an item with no path keeps its tokens under an empty path, and an assembly with no trace has no sources. A section's line saying it has no Utopia reader is not a source: it is no document, and counting it would make a Utopia assembly never empty. ([validated by leaves out the line saying a section has no Utopia reader, so it is not graded as a source @d952a6b0](apps/lore-api/src/work/context-evals/assembled-for-eval.test.ts#L64), [validated by lists the path and tokens of every item in an included section @2bbd43ef](apps/lore-api/src/work/context-evals/assembled-for-eval.test.ts#L27), [validated by leaves out the items of a section the budget dropped @b369fea7](apps/lore-api/src/work/context-evals/assembled-for-eval.test.ts#L45), [validated by counts an item with no path under an empty path, so its tokens still weigh on the total @8ce7d3d8](apps/lore-api/src/work/context-evals/assembled-for-eval.test.ts#L58), [validated by returns no sources when the assembly carried no trace @40649b55](apps/lore-api/src/work/context-evals/assembled-for-eval.test.ts#L77))
- FR3.2 — An eval assembles passively: `assembleContext({ passive: true })` writes nothing, where an agent's assembly audits its memory searches. ([validated by writes nothing to the database when the default template is assembled passively @d163b753](libs/server-core/src/work/context/context-assembly.test.ts#L316), [validated by audits its memory searches when the default template is assembled for an agent @d4b1b1d3](libs/server-core/src/work/context/context-assembly.test.ts#L337))
- FR3.3 — A passive memory search (`searchMemories({ passive: true })`) returns what it found without strengthening it and without an audit row, so two hundred eval questions a night raise no memory's rank. A search that is not passive does both. ([validated by leaves no trace of a passive search: no retrieval UPDATE and no audit row for the episode e1 it returned @b01fd0ab](libs/shared/src/outbound/project/knowledge/memory-search.test.ts#L102), [validated by strengthens the episode e1 it returned and audits the search when it is not passive @8e61eac2](libs/shared/src/outbound/project/knowledge/memory-search.test.ts#L126))

## Running the evals

- FR5.1 — `scripts/context-evals/run.mjs` runs from a developer machine against the deployed lore-api, one repository at a time, so one repository below the bar neither hides nor cancels another. A run can name one repository, the sample size, or one document of that repository. Nothing runs it on a schedule.
- FR5.2 — The repositories are every onboarded repository whose onboarding pull request merged, read from `GET /api/repos`; a run that names one repository evaluates that one without asking, and refuses a name that is not `owner/name`. ([validated by lists every repository whose onboarding pull request merged @2255acd7](scripts/context-evals/repos.test.mjs#L11), [validated by evaluates only re-cinq/Otto when the run names it, without asking Lore @7f42d5f2](scripts/context-evals/repos.test.mjs#L24), [validated by refuses a repository name that is not owner/name @ff83c5c5](scripts/context-evals/repos.test.mjs#L35))
- FR5.3 — A repository's job lists its documents (FR4.3) and posts each of the day's documents to `POST /api/context-evals` with the bearer token. A run that names one document evaluates that document only, without listing or sampling. ([validated by lists the repository's documents and posts each one with the bearer token @c5b70e7c](scripts/context-evals/run.test.mjs#L77), [validated by evaluates only adrs/ADR-7.md when the run names that document, without listing or sampling @2647c55b](scripts/context-evals/run.test.mjs#L223))
- FR5.4 — The day's documents are a window of 20 that moves on by 20 every day over a fixed shuffle of the repository's documents: the same date picks the same documents whatever order the list arrives in, the next night picks others, and every document is evaluated once every `ceil(n / 20)` nights. A repository with 20 documents or fewer has all of them evaluated every night. ([validated by returns all 7 documents, sorted, when the sample of 20 is larger than the list @dae79951](scripts/context-evals/sample.test.mjs#L8), [validated by picks 20 distinct documents out of 50 @2598e667](scripts/context-evals/sample.test.mjs#L15), [validated by picks the same 20 documents again for the same date, whatever order the list arrives in @da132048](scripts/context-evals/sample.test.mjs#L22), [validated by picks 20 other documents the next night @bb1b65ae](scripts/context-evals/sample.test.mjs#L29), [validated by covers all 50 documents in 3 consecutive nights of 20 @db31ba80](scripts/context-evals/sample.test.mjs#L39), [validated by returns no documents for an empty list @722f3d49](scripts/context-evals/sample.test.mjs#L49), [validated by orders two documents by code unit, not by locale, so every runner picks the same window @7a4b43b2](scripts/context-evals/sample.test.mjs#L53))
- FR5.5 — A repository passes on what could be answered: it may miss 15% of the run's questions, rounded down, and always at least one, so a repository of four documents does not turn red on a single miss. A run of one document, which is a person checking that document, has no miss to spare. `found` gates nothing: a question answered correctly from other documents is Lore doing its job, and the document that was not returned is listed for whoever reads the run. A repository with no ADRs or specs passes with nothing evaluated. `useful_share` is reported as the mean over the day's documents and gates nothing. ## The model

Decision: the eval's model calls go through `Llm.for("eval")` (`specs/shared-utilities`, FR — Llm.for), so the vendor is configuration. The lore-api chart sets `LORE_EVAL_LLM_PROVIDER=vertex` and `LORE_EVAL_LLM_MODEL=gemini-3-flash-preview` *(amended 2026-11-13, #4542: Vertex answered 404 for `gemini-2.5-flash` in the project lore-api runs in since 2026-11-06, so every eval failed)*; Vertex is reached under the pod's own Google identity and no model key is stored. Writing a question and judging an answer against its document are easy tasks, so the cheapest model that judges reliably is the right one.
