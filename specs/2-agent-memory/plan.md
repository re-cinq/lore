## Implementation Phases

### Phase 1: Core Memory MCP Tools

#### 1.1 Agent ID Generation

**Files:** `mcp-server/src/agent-id.ts`, `scripts/install.sh`

`install.sh` generates `~/.lore/agent-id` (UUID v4) on first install. Klaus pods
set `LORE_AGENT_ID` to their pod name.

Resolution order in `resolveAgentId()`:
1. Explicit `agent_id` parameter on any tool call
2. `LORE_AGENT_ID` env var (K8s pods)
3. `~/.lore/agent-id` file
4. Auto-generate UUID, write to `~/.lore/agent-id`

#### 1.2 PostgreSQL Schema

**Applied via:** `scripts/infra/setup-memory-schema.sh`

All tables in a dedicated `memory` schema within the existing `lore` database.

**`memory.memories`** — core memory store

| Column              | Type        | Notes                                          |
|---------------------|-------------|------------------------------------------------|
| id                  | UUID        | PK                                             |
| agent_id            | TEXT        | NOT NULL, indexed                              |
| key                 | TEXT        | NOT NULL                                       |
| value               | TEXT        | NOT NULL                                       |
| embedding           | VECTOR(768) | Nullable; populated async by Vertex AI         |
| version             | INTEGER     | Latest version; previous versions in `memory_versions` |
| is_deleted          | BOOLEAN     | DEFAULT FALSE; soft delete                     |
| ttl_seconds         | INTEGER     | Nullable                                       |
| expires_at          | TIMESTAMPTZ | Nullable; computed from ttl                    |
| pool_id             | UUID        | Nullable FK to `shared_pools`                  |
| repo                | TEXT        | Nullable; scopes memory to a specific repo     |
| retrieval_count     | INTEGER     | DEFAULT 0; incremented on every search hit     |
| last_retrieved_at   | TIMESTAMPTZ | Nullable; updated on every search hit          |
| half_life_days      | INTEGER     | DEFAULT 60; per-memory decay rate              |
| created_at          | TIMESTAMPTZ | DEFAULT now()                                  |

- UNIQUE on `(agent_id, key, version)`
- HNSW index on `embedding`
- Partial index on active rows: `WHERE is_deleted = FALSE AND (expires_at IS NULL OR expires_at > now())`

**`memory.memory_versions`** — full version history

| Column    | Type        | Notes                     |
|-----------|-------------|---------------------------|
| id        | UUID        | PK                        |
| memory_id | UUID        | FK to `memories.id`       |
| version   | INTEGER     | NOT NULL                  |
| value     | TEXT        | NOT NULL                  |
| embedding | VECTOR(768) | Nullable                  |
| created_at| TIMESTAMPTZ | DEFAULT now()             |

- UNIQUE on `(memory_id, version)`
- Every write (including the first) creates a row here

**`memory.facts`** — individually searchable facts linked to memories or episodes

| Column            | Type        | Notes                                        |
|-------------------|-------------|----------------------------------------------|
| id                | UUID        | PK                                           |
| memory_id         | UUID        | Nullable FK to `memories.id`                 |
| episode_id        | UUID        | Nullable FK to `episodes.id`                 |
| fact_text         | TEXT        | NOT NULL                                     |
| embedding         | VECTOR(768) | Nullable; HNSW indexed                       |
| confidence        | TEXT        | `verified`/`observed`/`inferred`/`stale`     |
| valid_from        | TIMESTAMPTZ | DEFAULT now()                                |
| valid_to          | TIMESTAMPTZ | Nullable; set when a contradicting fact invalidates this one |
| retrieval_count   | INTEGER     | DEFAULT 0                                    |
| last_retrieved_at | TIMESTAMPTZ | Nullable                                     |
| half_life_days    | INTEGER     | DEFAULT 30                                   |
| created_at        | TIMESTAMPTZ | DEFAULT now()                                |

- When a new fact has cosine similarity >= 0.92 to an existing fact, the old fact
  is invalidated (`valid_to = now()`) and a record is written to `fact_conflicts`.
- Conflict detection is automatic on every `write_episode` call.

**`memory.episodes`** — raw text blobs for passive capture

| Column       | Type        | Notes                                             |
|--------------|-------------|---------------------------------------------------|
| id           | UUID        | PK                                                |
| agent_id     | TEXT        | NOT NULL                                          |
| content      | TEXT        | Privacy-filtered via `redactSecrets()` on write   |
| content_hash | TEXT        | SHA-256 of content; deduplicates on `(agent_id, content_hash)` |
| source       | TEXT        | Originating system (e.g. `loretask-watcher`)      |
| ref          | TEXT        | Nullable; task ID, PR number, or other reference  |
| created_at   | TIMESTAMPTZ | DEFAULT now()                                     |

**`memory.snapshots`** — reference-based crash recovery

| Column      | Type        | Notes                                              |
|-------------|-------------|----------------------------------------------------|
| id          | UUID        | PK                                                 |
| agent_id    | TEXT        | NOT NULL                                           |
| memory_refs | JSONB       | Array of `{memory_id, version}`; no data copied    |
| trigger     | TEXT        | `manual` or `auto`                                 |
| created_at  | TIMESTAMPTZ | DEFAULT now()                                      |

**`memory.shared_pools`** — named spaces shared across agents

| Column     | Type | Notes                               |
|------------|------|-------------------------------------|
| id         | UUID | PK                                  |
| name       | TEXT | UNIQUE; created implicitly on first write |
| created_by | TEXT | agent_id of creator                 |
| created_at | TIMESTAMPTZ | DEFAULT now()                |

**`memory.entities`** + **`memory.edges`** — live knowledge graph

| Column (entities) | Type | Notes                             |
|-------------------|------|-----------------------------------|
| id                | UUID | PK                                |
| name              | TEXT | UNIQUE                            |
| entity_type       | TEXT | service/team/technology/etc       |

| Column (edges) | Type        | Notes                             |
|----------------|-------------|-----------------------------------|
| id             | UUID        | PK                                |
| source_id      | UUID        | FK to `entities.id`               |
| target_id      | UUID        | FK to `entities.id`               |
| relation_type  | TEXT        | NOT NULL                          |
| valid_to       | TIMESTAMPTZ | Nullable; NULL = current          |

Updated incrementally on every `write_episode` call. Used by graph augmentation
in `search_memory`.

**`memory.fact_conflicts`** — contradiction log

Stores a record before any fact is invalidated. Context assembly prefixes
`[CONFLICT]` on facts with recent (7-day) conflicts to surface disputed knowledge.

**`memory.audit_log`** — append-only operations log

| Column     | Type        | Notes                                          |
|------------|-------------|------------------------------------------------|
| id         | UUID        | PK                                             |
| agent_id   | TEXT        | NOT NULL                                       |
| operation  | TEXT        | write/read/search/delete/snapshot/restore/etc  |
| memory_key | TEXT        | Nullable                                       |
| pool_name  | TEXT        | Nullable                                       |
| metadata   | JSONB       | Nullable; query, result count, latency, scores |
| created_at | TIMESTAMPTZ | DEFAULT now()                                  |

#### 1.3 MCP Memory Tools

**Files:** `mcp-server/src/memory.ts`, `mcp-server/src/index.ts`

**`write_memory`** — store or update a key-value memory

```typescript
{
  key: string,
  value: string,
  agent_id?: string,      // defaults to ~/.lore/agent-id
  ttl?: number,           // seconds; omit for permanent
  embedding?: number[],   // pre-computed vector; Vertex AI used if omitted
  repo?: string           // repo-scoped memories (for cross-repo filtering)
}
```

Behavior: resolve agent ID → generate embedding via `getQueryEmbedding()` →
upsert into `memories` (increment version, write to `memory_versions`) → log to
`audit_log`. Returns `{ key, version, agent_id, created_at }`.

**`read_memory`** — retrieve a memory by key

```typescript
{
  key: string,
  agent_id?: string,
  version?: string  // "all" for full history, or specific version number
}
```

**`delete_memory`** — soft-delete a memory

```typescript
{ key: string, agent_id?: string }
```

Sets `is_deleted = TRUE`. Does not remove `memory_versions` or `facts`.

**`list_memories`** — paginated listing of active memories

```typescript
{ agent_id?: string, limit?: number, offset?: number }
```

Excludes deleted and expired entries.

**`search_memory`** — hybrid semantic + keyword search

```typescript
{
  query: string,
  agent_id?: string,          // scope to agent (omit for cross-agent)
  pool?: string,              // search within a named pool
  limit?: number,             // default 10
  include_invalidated?: boolean  // include historical/superseded facts
}
```

Returns `MemorySearchResult[]` with fields: `key, value, score, agent_id, source,
id, confidence`. The `source` field distinguishes `memory`, `fact`, `episode`,
and `graph` results.

**`write_episode`** — ingest raw text; auto-extracts facts and updates knowledge graph

```typescript
{
  content: string,  // raw text (conversation, review, observation)
  source: string,   // originating system
  ref?: string,     // task ID, PR number, or other reference
  agent_id?: string
}
```

Content is privacy-filtered via `redactSecrets()` before storage. Deduplicates
via SHA-256 hash. Triggers async fact extraction and knowledge graph update.

**`query_graph`** — query the live knowledge graph

```typescript
{
  entity: string,   // entity name to look up
  depth?: number    // default 1 (1-hop neighbors)
}
```

Returns entity nodes and edges from `memory.entities` + `memory.edges`.

**`agent_stats`** — health, memory count, episode count, facts, searches, daily breakdown

```typescript
{ agent_id?: string }
```

#### 1.4 Search Architecture (`memory-search.ts`)

Search combines four result sets via Reciprocal Rank Fusion (RRF_K = 60):
1. Vector search on `memories.embedding`
2. Vector search on `facts.embedding` (memories + episodes)
3. Keyword ILIKE on `memories.value`/`memories.key`
4. Keyword ILIKE on `facts.fact_text`

**Session diversification:** Results are capped at 3 per `(agent_id, source)` combo
before applying the limit. Prevents one verbose session from dominating results.
Inspired by agentmemory.

**Graph augmentation:** When `graphAugmentEnabled = true`, entity names detected in
the top results are used to fetch 1-hop neighbors from `memory.entities` +
`memory.edges`. Graph results get a score below the worst direct result.
Entity cache refreshes every 5 minutes.

**Retrieval strengthening:** Fire-and-forget UPDATE after every search increments
`retrieval_count`, sets `last_retrieved_at`, extends `half_life_days` (+2, capped
at 365), and revives `stale` facts to `observed` confidence.

**Transfer scoring:** `computeTransferScore(text)` scores portability for cross-repo
filtering. Portable keywords (error, pattern, gotcha, convention) boost score;
local keywords (config, deploy, url, secret) reduce it. Only facts scoring >=
0.5 pass through in cross-repo context assembly.

**Keyword-only degradation:** Runs even when Vertex AI embedding is unavailable,
providing results via ILIKE on both memories and facts.

#### 1.5 File-Backed Fallback (`memory-file.ts`)

When PostgreSQL is unavailable, all memory tools fall back to JSON files in
`~/.lore/memory/`:

```
~/.lore/memory/
  <agent-id>/
    memories.json       # { key: { value, version, created_at, ttl_seconds, is_deleted } }
    versions.json       # { key: [{ version, value, created_at }] }
    snapshots.json      # [{ id, memory_refs, trigger, created_at }]
  shared/<pool-name>/
    memories.json       # Pool entries
  audit.jsonl           # Append-only, one JSON object per line
```

No embeddings in file mode — `search_memory` degrades to case-insensitive
substring matching. Fact extraction and episode writing are skipped.

### Phase 2: Advanced Features

#### 2.1 Fact Extraction (`facts.ts`)

Async fact extraction triggered by `write_episode` and optionally by `write_memory`.

LLM configuration via env vars:
- `LORE_FACT_LLM=claude` (default) / `openai` / `ollama`
- `LORE_FACT_MODEL` — specific model ID
- `LORE_OLLAMA_URL` — for local Ollama

Prompt: extracts individual factual statements, one per line. Each fact is stored
in `memory.facts` with its own embedding and `confidence = 'observed'`. Facts from
episodes link via `episode_id`; facts from memories link via `memory_id`.

If the extraction LLM is unreachable: memory write succeeds immediately. Fact
extraction is queued with 3-attempt exponential backoff. Memory is searchable as
raw text until extraction completes.

#### 2.2 Shared Memory Pools

**`shared_write`** — write to a named pool (creates pool implicitly on first write)

```typescript
{ pool: string, key: string, value: string, agent_id?: string }
```

**`shared_read`** — read from a pool

```typescript
{ pool: string, key?: string }  // key omitted = list all entries
```

Pool-scoped search via `search_memory(query, pool: "pool-name")`.

#### 2.3 Snapshots

**`create_snapshot`** — reference-based snapshot of all current agent memories

```typescript
{ agent_id?: string, trigger?: 'manual' | 'auto' }
```

Stores `memory_refs: [{memory_id, version}]` — no data copied.

**`restore_snapshot`** — revert memories to a snapshotted state

```typescript
{ snapshot_id: string }
```

Reads `memory_versions` to restore values and embeddings. Soft-deletes memories
created after the snapshot. Runs in a single serializable transaction.
Target: under 1 second for 10,000 memories.

#### 2.4 TTL and Expiration

CronJob (hourly) hard-deletes memories 24 hours after their `expires_at`:

```sql
DELETE FROM memory.memories WHERE expires_at < now() - interval '24 hours';
```

Expired memories are excluded from search immediately via the partial index.
The CronJob is a cleanup-only pass — no agent logic.

#### 2.5 Confidence Tiers

Facts carry a `confidence` column with four tiers:
- `verified` — human-confirmed
- `observed` — sourced from an episode (default)
- `inferred` — sourced from a memory write
- `stale` — unretrieved for 30+ days

Assembled context includes confidence annotations. Stale facts get a -1
importance penalty in the decay scorer. Retrieving a stale fact revives
it to `observed`.

### Phase 3: ADR-014 — Intelligent Memory Lifecycle

Implemented as a post-Phase-2 enhancement per
[ADR-014](../../adrs/ADR-014-passive-memory-capture.md) (accepted 2026-04-06).
Addresses three gaps in the original design: agents skipping `write_episode`,
unbounded memory growth, and noisy raw facts.

#### 3.1 Passive Session Capture (`session-tracker.ts`)

Tracks all MCP tool calls in a 500-entry in-memory ring buffer. On process exit,
dumps to `~/.lore/last-session.json`:

```json
{
  "startTime": "...",
  "endTime": "...",
  "summary": "Session: 42min, 87 tool calls, 0 errors\n...",
  "toolCalls": 87,
  "log": [{ "tool": "search_context", "timestamp": "...", "durationMs": 120, "success": true }, ...]
}
```

The `install.sh` Stop hook POSTs this file to `/api/session-summary`, which runs
LLM summarization and writes an episode + extracts facts. Zero agent cooperation
required.

#### 3.2 Post-Task Auto-Curation (`episode-writer.ts`)

After every task completion (PR created, no-changes, failure, feature-request,
onboard), `writeEpisodeWithCuration()` is called by `loretask-watcher` and the
agent worker:

1. `writeEpisode()` — inserts into `memory.episodes` with privacy filtering and
   SHA-256 deduplication. Returns `null` on duplicate (idempotent).
2. `callLLM()` via Haiku — extracts a "lesson learned" in 1-2 sentences.
   Prompt: "Extract one concise lesson learned from this task outcome..."
3. Stores the lesson as `memory.memories` with key `auto-curation/{ref}`.

Skips lesson extraction if no `ANTHROPIC_API_KEY` or if the episode was a
duplicate.

#### 3.3 Importance-Based Decay (`importanceDecayJob`)

Runs daily at 5 AM. Finds agents exceeding 500 memories, scores candidates by
importance (0-10), evicts lowest-scoring entries:

```
strength = 0.5^(effective_age / half_life_days)
score    = round(strength * 10)

Adjustments:
  value.length < 50        → -2
  value.length > 500       → +1
  key has "gotcha"/"decision"   → +2
  key has "convention"/"pattern"→ +2
  key starts "auto-curation/"   → -1
  key starts "session-summary/" → -1
  retrieval_count >= 20    → +2
  retrieval_count >= 5     → +1
  confidence == "stale"    → -1
```

Effective age uses `last_retrieved_at` when available (rewarding frequently
accessed memories), falling back to `created_at`.

Also:
- Hard-deletes invalidated facts older than 30 days beyond the 2,000-fact cap
- Transitions unretrieved facts to `stale` confidence after 30 days

#### 3.4 Automatic Consolidation (`consolidationJob`)

Runs daily at 5:30 AM. Groups recent facts (7-day lookback, minimum 5 facts)
by repo. Calls Haiku to extract 1-3 higher-level patterns per repo:

Prompt: "Identify 1-3 higher-level patterns or insights... Each pattern should be
actionable. Return each pattern prefixed with 'PATTERN: '"

Stores each extracted pattern as a `consolidated/{repo}/{timestamp}` memory under
`agent_id = 'consolidation'`. Reduces noisy raw facts into actionable insights
for future search.

Requires `ANTHROPIC_API_KEY`. Skips repos with fewer than 3 recent facts.

## Privacy and Security

All memory writes (episodes, memories) pass through `sanitizeContent()` /
`redactSecrets()` from `@re-cinq/lore-shared` before storage. Strips API keys,
JWTs, private keys, connection strings, and bearer tokens. Applied on both the
MCP tool path and the REST API path.

Agent isolation enforced by `agent_id` WHERE clauses. Agent A cannot read
Agent B's private memories. Shared pools are explicit opt-in only.

## Risk Register

| Risk | Impact | Mitigation Applied |
|------|--------|--------------------|
| Embedding latency on write | Medium | Async embedding — write returns immediately with null embedding; keyword search covers until vector arrives |
| Fact extraction LLM unavailable | Low | Write succeeds; extraction queued with 3-attempt exponential backoff |
| Unbounded memory growth | High | Importance decay evicts beyond 500-memory cap; fact cap at 2,000 |
| Session learnings lost on agent exit | High | Passive session tracker + Stop hook captures everything without agent cooperation |
| Raw facts are noisy | Medium | Daily consolidation job synthesizes patterns via Haiku |
| Fact contradictions create confusion | Medium | Automatic conflict detection; `[CONFLICT]` prefix in assembled context |
| Snapshot restore correctness with concurrent writes | Medium | Serializable transaction; concurrent writes blocked briefly |
