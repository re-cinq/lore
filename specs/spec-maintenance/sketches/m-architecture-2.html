Order 0 guard-open-pr → 1 align-implementation → 2 prune-decisions → 3 enforce-speckit → 4 check-length → 5 lint
0  guard-open-pr
Reads
Open pull requests in the repository that touch the target spec file
Does
Halts the run immediately if any open PR already modifies that spec; logs the skip so the board shows "skipped — open PR" rather than a failure
Does not
Block on PRs that touch only other spec files • Close or dismiss the conflicting PR
1  align-implementation
Reads
Spec statements that carry a test-link parenthetical pointing to a test
Does
Checks each linked statement against the current test result; rewrites any statement whose wording no longer matches what the test asserts
Does not
Touch statements without a test link • Run, modify, or reference test files
2  prune-decisions
Reads
Spec statements carrying inline amendment markers such as "(added 2026-10-01, amended 2026-10-23)"
Does
Rewrites each marked statement in the present tense and strips the history annotation — the commit history already holds the full timeline
Does not
Choose between two conflicting statements • Remove content that has no amendment marker
3  enforce-speckit
Reads
The full spec file and the SpecKit template expected by the planning tools
Does
Validates section order, required rows (Owner, Status, Linked plan), and statement format; rewrites non-conforming sections to match the template
Does not
Change a statement's meaning — only its formatting and placement
4  check-length
Reads
The spec file after the other three passes complete
Does
Counts lines; if the count exceeds ~500 it identifies coherent sub-features, drafts each as a new spec in a sibling feature directory, links extracted sections back from the original, and sets a split flag so the assembly line opens a separate PR for human review
Does not
Commit the split directly — a split always goes to a separate PR • Auto-merge its own split pull requests
5  lint
Reads
All spec files written during this run
Does
Runs prettier --write on each changed file; if no bytes changed the run ends with "no changes"; if bytes changed it signals the assembly line to open a cleanup PR (and a separate split PR when the split flag is set)
Does not
Validate content logic — lint is format-only • Run against code or test files
