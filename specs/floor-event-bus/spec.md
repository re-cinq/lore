# Feature Specification: Floor Event Bus

| Field   | Value                    |
|---------|--------------------------|
| Feature | Floor Event Bus          |
| Status  | In Progress              |
| Owner   | Platform Engineering     |
| Builds on | [ADR-015](../../adrs/ADR-015-webhook-driven-review-reactor.md) |

The event bus is the one durable, at-least-once path every trigger in Lore takes: an event is written to `pipeline.events`, copied into one `pipeline.event_deliveries` row per subscriber, and each subscriber claims, retries and dead-letters its own rows. The bus outlived the Floor it is named after: lore-api and the stations service produce its events today, and the stations service is its only consumer and its keeper.

## Background

The bus was built for the event loop and handler registry inside Lore's own Floor (`apps/floor`). That Floor was deleted on 2026-10-02 (`specs/external-floor` FR16), with its loop, its registry and its `floor` subscription, which migration 0095 removes so that no event keeps a pending delivery nobody claims. The separate event-router was folded into lore-api (ADR-044, amendment of 2026-10-02). The shared drain loop, the retry decision and the delivery store stayed in `libs/shared/src/outbound/project/events/`, and the stations service (`apps/stations/src/events/`) runs them.

`pipeline.events` carries no status. Migration 0072 dropped its `status`, `attempts`, `claimed_at`, `next_attempt_at`, `handled_at` and `error` columns, because consumption happens on the subscriber's own delivery row and never on the event.

### Producing events

- FR1. lore-api's `POST /api/webhook/github` (`apps/lore-api/src/transport/routes/webhooks/webhook-github.ts`) verifies the delivery's HMAC signature, maps it with `mapGitHubEvent` to `github.*` events and writes each to `pipeline.events`, the first under the dedupe key `github:<delivery id>` and the Utopia mirror's under `github:<delivery id>:utopia`. ### Claiming and dispatching
