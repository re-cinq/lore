# Lore Derived Code Graph

| Field  | Value |
|--------|-------|
| Status | Implemented |

At ingest time, for every onboarded repo, derive and write graph edges that today exist only if someone calls `lore_write_episode`:

- Statement 1. After one ingest, `lore_query_graph({entity: "<library>"})` returns a `depends-on` edge from the consumer carrying the `github:` specifier and `pinned: false`. ([validated by emits a depends-on edge from the consumer to the library @8a22b12f](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L56), [derives a depends-on edge from a package.json with a github: specifier @a6e40ff4](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L5), [marks a github: specifier without a commit ref as not pinned @ae4c60d4](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L18), [marks a github: specifier with a commit ref as pinned @43b38ca2](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L29), [returns empty for invalid JSON @aab07506](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L40), [derives edges from peerDependencies too @a3ea1483](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L46))
- Statement 2. `lore_query_graph({entity: "<exported symbol>", relation_type: "uses"})` returns the importing files with their repos; an export with no importers returns an explicit derived-and-empty result, distinguishable from not-derived. ([validated by returns the importing file for a used symbol @9588f0e1](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L67), [returns a none sentinel for an export with no importers @2e4a7242](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L76))
- Statement 3. The `exports` edge set for the library lists each public export of its entry module with kind and source path. ([validated by lists each public export of the entry module in an exports edge set @4b838b4a](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L87), [lists no exports from a module that is not the entry module @9f5b3f25](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L104))
- Statement 4. A per-repo import-set query returns exactly the symbols the consumer imports and shows zero importers for the library's unused modules. ([validated by per-repo import set contains used symbols and omits unused ones @be12ffc5](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L113))
- Statement 5. `lore_query_graph({entity: "<subclass>"})` returns an `extends` edge to its base type with the added member and its source path. ([validated by emits an extends edge from the subclass to its base type @ab70cbf0](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L123))
- Statement 6. Re-ingesting an unchanged repo produces an identical edge set: derivation is deterministic and needs no `lore_write_episode`. ([validated by re-ingesting an unchanged repo produces an identical edge set @f64c765e](apps/lore-api/src/integration-tests/derive-code-graph.acceptance.test.ts#L133))
- Statement 7. Edges are derived for all onboarded repos, including those where `auto_ingest_graph` is off. ([validated by derives edges from any repo without an auto_ingest_graph opt-in @42b8b5d4](apps/lore-api/src/work/spec-trace/derive-code-graph.test.ts#L57))
