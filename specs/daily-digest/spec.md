# Feature Specification: Daily Digest to Slack

| Field    | Value                                         |
|----------|-----------------------------------------------|
| Feature  | Daily Digest to Slack                         |
| Branch   | feat/daily-digest-core                        |
| Status   | In Progress                                   |
| Created  | 2026-09-25                                    |
| Owner    | Platform Engineering                          |

The daily digest tells a project's Slack channel, once a day, what each person did and what they are doing next, so people stop stepping on each other's tasks and the stand-up can be about blockers instead of reports. Lore collects the facts from GitHub, an agent writes a one-sentence intro and sums up each person's work in a few themed bullets, and the whole thing lands as a reply in that week's thread.

The first version listed every merged pull request and open issue per repo, grouped, with a voice monologue, an aside after every section and a closing speech. People found it too long, and most of them read only their own lines (feedback, 2026-10-23); one line per person is what they asked for, and the full list belongs on the repository's changelog page.

## Problem Statement

Otto is three repos (lore, ai-agent-subsystem, planning-station) worked by a
few people and several agents. Nobody has an overview of what merged yesterday
or who holds which issue without opening every repo. The Slack thread that
prompted this (2026-09-25) settled on: one channel per project, a daily post
per channel, per-repo sections in it, the week's posts collected in one thread
so messages to humans are not buried, and an agent-written intro and closing
line so the post reads like a colleague wrote it and never the same twice.

Nothing in Lore holds this today: human merges are not stored (webhook events
are pruned after seven days), the GitHub port has no "merged since", "closed
since" or assignee reads, no Slack post has ever used a thread, and no setting
carries a time of day.

## Background: how it runs

An assembly line with one agent node, `refine`, and the exit marker. The
Floor's cron emitter `daily_digest` ticks every 15 minutes; the tick handler
decides per repo whether its digest is due and starts one run per Slack
channel. The refine agent's input file, `digest-draft.md`, is served by a Floor
route that collects the repos' changes from GitHub on the fly and stores the
draft on the run. The agent uploads `digest.md`, and the Floor's upload receiver
posts it to Slack. A failed or dead agent still gets the draft posted.

## FR1 — Settings

- A repo opts in through `settings.digest` next to its `slack_channel_id`: `enabled`, `time` (`HH:MM`), `days` (JS weekdays, Sunday 0), `timezone` (IANA), `sections` (any of `implemented`, `roadmap`, `summary`) and an optional `voice`. Migration 0117 removed the old `morale` section and `group_by` from stored blocks. ([validated by returns every default when the block is absent @17525193](libs/shared/src/domain/digest-settings.test.ts#L5))

## FR2 — When a digest is due

- A repo's digest is due when it is enabled, the local weekday is one of its days, the local time of day has reached its time, and nothing was posted for it yet that local day. ## FR8 — One run per channel, one message per channel

- Every 15 minutes the tick reads every onboarded repo's settings in one query, keeps the enabled repos with a channel whose digest is due, and starts one run per channel carrying every due repo. The run is hosted by the channel's first repo by name, due or not, so its guards always look under the same repo, and it is keyed on the channel, the local day and the earliest scheduled time among the due repos, so repos on one channel scheduled at different times are separate runs under separate caps. ([validated by returns every onboarded repo with its raw settings @c445a2ca](libs/shared/src/outbound/project/settings/settings.test.ts#L48))
- The run's args carry each repo's window (from its last finished post, or 24 hours back), and sections as `digest_repos`, which one codec wraps and unwraps, plus `ref` set to the host repo's default branch since the run's own branch is only a lease key. ([round-trips digest_repos through the line args @085d6388](libs/shared/src/work/digest/codec.test.ts#L14), [rejects malformed digest_repos naming the field @4941e5a4](libs/shared/src/work/digest/codec.test.ts#L18))
- A channel whose run for the slot is in flight is skipped, and a slot starts at most three runs a day. A repo whose due check throws is logged and left out, and a channel whose start fails is logged while the other channels still start; the host's default branch is read before the job_run is minted, and a start that fails after it fails that job_run. `params.repo` narrows the tick and `params.force` skips the due check.
- A message over Slack's limit is posted as consecutive replies in the thread, broken by line and never inside a line; the people go at most 20 attachments a reply, each whole *(amended 2026-10-27)*. ([validated by puts 3 people into messages of at most 2 attachments @255b9ca4](libs/shared/src/work/digest/slack-sections.test.ts#L48), [validated by returns one chunk when the text fits @80e75f15](libs/shared/src/work/digest/split-for-slack.test.ts#L5), [breaks only at a line end when the next line would exceed the limit @0bf25feb](libs/shared/src/work/digest/split-for-slack.test.ts#L9), [keeps every line whole @70a0fed5](libs/shared/src/work/digest/split-for-slack.test.ts#L16), [hard-cuts a single line longer than the limit @fdf7f05d](libs/shared/src/work/digest/split-for-slack.test.ts#L22), [drops blank leading and trailing lines from every chunk @af1bd6c2](libs/shared/src/work/digest/split-for-slack.test.ts#L26), [posts a long digest as several replies inside the week's thread @7844050e](libs/shared/src/work/digest/deliver-digest.test.ts#L168))

## FR9 — The refine agent

- The line is one agent node, `refine`, on the `digest-refine` station, and the exit; a failed refine still reaches the exit.
- The draft is served as the pod's input file `digest-draft.md`: collected from GitHub for every repo of the run when the pod first asks, kept on the run so a retry downloads the same draft, and 404 for a run that is not a digest run.
