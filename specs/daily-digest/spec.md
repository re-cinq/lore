# Feature Specification: Daily Digest to Slack

| Field    | Value                                         |
|----------|-----------------------------------------------|
| Feature  | Daily Digest to Slack                         |
| Branch   | feat/daily-digest-core                        |
| Status   | In Progress                                   |
| Created  | 2026-09-25                                    |
| Owner    | Platform Engineering                          |

The daily digest tells a project's Slack channel, once a day, what changed in its repos and who is working on what, so people stop stepping on each other's tasks and the stand-up can be about blockers instead of reports. Lore collects the facts from GitHub, an agent writes a fresh intro and a fresh ending around them, and the whole thing lands as a reply in that week's thread.

## Problem Statement

Otto is three repos (lore, ai-agent-subsystem, planning-station) worked by a
few people and several agents. Nobody has an overview of what merged yesterday
or who holds which issue without opening every repo. The Slack thread that
prompted this (2026-09-25) settled on: one channel per project, a daily post
per channel, per-repo sections in it, the week's posts collected in one thread
so messages to humans are not buried, and an agent-written intro and closing
line so the post reads like a colleague wrote it and never the same twice.

Nothing in Lore holds this today: human merges are not stored (webhook events
are pruned after seven days), the GitHub port has no "merged since", "closed
since" or assignee reads, no Slack post has ever used a thread, and no setting
carries a time of day.

## Background: how it runs

An assembly line with one agent node, `refine`, and the exit marker. The
Floor's cron emitter `daily_digest` ticks every 15 minutes; the tick handler
decides per repo whether its digest is due and starts one run per Slack
channel. The refine agent's input file, `digest-draft.md`, is served by a Floor
route that collects the repos' changes from GitHub on the fly and stores the
draft on the run. The agent uploads `digest.md`, and the Floor's upload receiver
posts it to Slack. A failed or dead agent still gets the draft posted.

## FR1 — Settings

- A repo opts in through `settings.digest` next to its `slack_channel_id`: `enabled`, `time` (`HH:MM`), `days` (JS weekdays, Sunday 0), `timezone` (IANA), `sections` (any of `implemented`, `roadmap`, `summary`, `morale`), `group_by` (`person` or `area`) and an optional `voice`. ([validated by returns every default when the block is absent](libs/shared/src/domain/digest-settings.test.ts#L5))
- An absent field takes its default: disabled, 09:00, Monday to Friday, Europe/Berlin, every section, grouped by person; a partial block keeps what it says and fills the rest. ([validated by keeps a partial block's values and fills the rest](libs/shared/src/domain/digest-settings.test.ts#L17), [returns disabled when enabled is absent](libs/shared/src/domain/digest-settings.test.ts#L28))
- The settings API refuses a malformed digest block (a weekday outside 0–6, a time that is not `HH:MM`, a timezone `Intl` cannot format in) with 400 and writes nothing, merges a well-formed one like any other setting, and takes `digest: null` as clearing the block. ([validated by returns 400 for a digest block with a weekday of 9](apps/lore-api/src/transport/routes/repos/repo-settings.test.ts#L216), [returns 400 for a digest block whose timezone is not an IANA zone](apps/lore-api/src/transport/routes/repos/repo-settings.test.ts#L231), [merges a well-formed digest block](apps/lore-api/src/transport/routes/repos/repo-settings.test.ts#L266), [merges digest: null so a repo can clear its digest block](apps/lore-api/src/transport/routes/repos/repo-settings.test.ts#L253))

## FR2 — When a digest is due

- A repo's digest is due when it is enabled, the local weekday is one of its days, the local time of day has reached its time, and nothing was posted for it yet that local day. ([validated by returns false when disabled](libs/shared/src/work/digest/decide-due.test.ts#L9), [returns true at 09:05 Berlin on a weekday with no prior post](libs/shared/src/work/digest/decide-due.test.ts#L19), [returns false before the scheduled time](libs/shared/src/work/digest/decide-due.test.ts#L29), [returns false on a weekday not in days](libs/shared/src/work/digest/decide-due.test.ts#L39), [returns false when already posted today in the repo's timezone](libs/shared/src/work/digest/decide-due.test.ts#L49), [returns true when the last post was yesterday](libs/shared/src/work/digest/decide-due.test.ts#L59))
- Local date, weekday and time are read in the repo's own timezone, so a post at 09:05 Berlin is due at 08:05 UTC after the October clock change. ([validated by returns true on Monday 2026-10-26 at 08:05Z, which is 09:05 Berlin after the clocks went back](libs/shared/src/work/digest/decide-due.test.ts#L69), [returns the local date, JS weekday and HH:MM in the timezone](libs/shared/src/work/digest/decide-due.test.ts#L81))

## FR3 — What is collected

- The implemented window opens at the repo's last digest post, or 24 hours back on the first run. ([validated by carries every repo's window, sections and grouping in the run's args, with ref set to the host repo's default branch](apps/floor/src/work/digest/fan-out.test.ts#L96), [opens the window at the repo's last finished post](apps/floor/src/work/digest/fan-out.test.ts#L147))
- Implemented changes are the PRs merged in the window, read newest first from GitHub's closed listing, which stops paging once it passes the cutoff, and the issues closed in the window with their assignees. ([validated by listMergedSince keeps only pulls merged at or after the cutoff, newest first](libs/shared/src/outbound/project/lib/platform-github.test.ts#L229), [listMergedSince stops paging once a closed pull is older than the cutoff](libs/shared/src/outbound/project/lib/platform-github.test.ts#L258), [listMergedSince keeps paging while every pull is inside the window](libs/shared/src/outbound/project/lib/platform-github.test.ts#L271), [listIssues maps assignee logins onto assignees and close time onto closedAt](libs/shared/src/outbound/project/lib/platform-github.test.ts#L284), [listIssues keeps only issues closed at or after since when listing closed ones](libs/shared/src/outbound/project/lib/platform-github.test.ts#L306))
- Roadmap is every open issue that has at least one assignee; an unassigned open issue says nothing about who is busy. ([validated by skips an open issue nobody is assigned to](libs/shared/src/work/digest/group.test.ts#L69))

## FR8 — One run per channel, one message per channel

- Every 15 minutes the tick reads every onboarded repo's settings in one query, keeps the enabled repos with a channel whose digest is due, and starts one run per channel carrying every due repo. The run is hosted by the channel's first repo by name, due or not, so its guards always look under the same repo, and it is keyed on the channel, the local day and the earliest scheduled time among the due repos, so repos on one channel scheduled at different times are separate runs under separate caps. ([validated by returns every onboarded repo with its raw settings](libs/shared/src/outbound/project/settings/settings.test.ts#L63), [skips repos whose digest is disabled or that have no channel](apps/floor/src/work/digest/fan-out.test.ts#L55), [starts one run per channel when two due repos share it, hosted by the first repo by name](apps/floor/src/work/digest/fan-out.test.ts#L66), [starts nothing before the repo's time of day](apps/floor/src/work/digest/fan-out.test.ts#L168), [keeps the channel's first repo as host when only a later repo is due, and lists every member](apps/floor/src/work/digest/fan-out.test.ts#L295), [keys a later slot of the same channel on its own time, so the morning's runs never count against it](apps/floor/src/work/digest/fan-out.test.ts#L315))
- The run's args carry each repo's window (from its last finished post, or 24 hours back), sections and grouping as `digest_repos`, which one codec wraps and unwraps, plus `ref` set to the host repo's default branch since the run's own branch is only a lease key. ([validated by carries every repo's window, sections and grouping in the run's args, with ref set to the host repo's default branch](apps/floor/src/work/digest/fan-out.test.ts#L96), [opens the window at the repo's last finished post](apps/floor/src/work/digest/fan-out.test.ts#L147), [round-trips digest_repos through the line args](libs/shared/src/work/digest/codec.test.ts#L15), [rejects malformed digest_repos naming the field](libs/shared/src/work/digest/codec.test.ts#L19))
- A channel whose run for the slot is in flight is skipped, and a slot starts at most three runs a day. A repo whose due check throws is logged and left out, and a channel whose start fails is logged while the other channels still start; the host's default branch is read before the job_run is minted, and a start that fails after it fails that job_run. `params.repo` narrows the tick and `params.force` skips the due check. ([validated by skips a channel whose run for today is in flight](apps/floor/src/work/digest/fan-out.test.ts#L179), [gives up on a channel after three runs in one day](apps/floor/src/work/digest/fan-out.test.ts#L197), [narrows to params.repo and force skips the due check](apps/floor/src/work/digest/fan-out.test.ts#L220), [leaves out a repo whose due check throws and still starts the others](apps/floor/src/work/digest/fan-out.test.ts#L274), [fails the orphaned job_run when the start throws and carries on with the next channel](apps/floor/src/work/digest/fan-out.test.ts#L231), [mints no job_run when reading the host's default branch fails](apps/floor/src/work/digest/fan-out.test.ts#L258))
- A message over Slack's limit is posted as consecutive replies in the thread, broken by line and never inside a line. ([validated by returns one chunk when the text fits](libs/shared/src/work/digest/split-for-slack.test.ts#L5), [breaks only at a line end when the next line would exceed the limit](libs/shared/src/work/digest/split-for-slack.test.ts#L9), [keeps every line whole](libs/shared/src/work/digest/split-for-slack.test.ts#L16), [hard-cuts a single line longer than the limit](libs/shared/src/work/digest/split-for-slack.test.ts#L22), [drops blank leading and trailing lines from every chunk](libs/shared/src/work/digest/split-for-slack.test.ts#L26), [posts a long digest as several replies inside the week's thread](apps/floor/src/work/digest/deliver-digest.test.ts#L140))
